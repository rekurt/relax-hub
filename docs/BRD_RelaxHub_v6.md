# BRD — RelaxHub

## Бизнес-требования к продукту

**Версия:** v6
**Дата:** 17.03.2026
**Источник:** SRS RelaxHub v3
**Назначение:** Бизнес-блоки, функциональные требования, правила и ограничения — без технической архитектуры, модели данных и контрактов API (см. отдельный документ TRD).

**Главное УТП:** Клиент бронирует баню онлайн → Владелец получает бесплатную CRM и ноль комиссии.

# 1. РОЛИ И КЛЮЧЕВЫЕ СЦЕНАРИИ

## 1.1 Гость (Клиент)

**Права:** регистрация, поиск, бронирование (мгновенное, по запросу, повторное), оплата (карта, СБП, Apple Pay, Google Pay, кошелёк, комбо), кошелёк, сообщения с владельцем, отзывы, уведомления, избранное, промокоды, реферальная ссылка, подарочные сертификаты, поддержка, удаление аккаунта.

**Ключевые сценарии:**

1. Регистрация
2. Поиск объекта по геолокации, дате, фильтрам
3. Просмотр карточки и сравнение объектов
4. Мгновенное бронирование с оплатой
5. Бронирование по запросу
6. Повторное бронирование
7. Изменение или отмена бронирования
8. Пополнение кошелька и оплата с кошелька
9. Оставление отзыва после визита
10. Активация подарочного сертификата
11. Подача жалобы / участие в споре

## 1.2 Владелец (Хозяин)

**Права:** регистрация, KYC, оферта; листинги (описание, фото, цены, календарь, add-ons); бронирования (подтверждение, отклонение, отмена, прибытие/убытие); сообщения с клиентами; отзывы; кошелёк (вывод, оплата услуг); CRM (база гостей, сегментация, рассылки); аналитика; продвижение; подписка; управление сотрудниками; API-интеграции.

**Ключевые сценарии:**

1. Онбординг через 7-шаговый мастер
2. Создание и модерация листинга
3. Настройка ценообразования (базовое, по дням, сезонное, праздничное)
4. Управление календарём доступности
5. Подтверждение / отклонение запросов на бронирование
6. Ответ на сообщения и отзывы
7. Вывод средств с кошелька
8. Просмотр аналитики и сравнение с конкурентами
9. Управление платным продвижением

## 1.3 Основные пользовательские флоу (happy path)

**Флоу 1 — Мгновенное бронирование:** Регистрация / Авторизация → Главный экран → Поиск → Фильтры → Карточка → Оформление (stepper) → Оплата → Подтверждение → История

**Флоу 2 — По запросу:** Регистрация / Авторизация → Карточка → Оформление → Холд → Ожидание владельца (≤ 24 ч) → [Одобрено] → Оплата → Подтверждение | [Отклонено] → Возврат

**Флоу 3 — Онбординг владельца:** Регистрация → KYC → Оферта → Мастер (7 шагов) → Модерация → Активен

**Флоу 4 — Обработка запроса:** Уведомление → Детали → Одобрить/Отклонить → Уведомление клиенту

**Флоу 5 — Отмена:** История → Детали → Отмена → Выбор возврата (кошелёк с бонусом / карта) → Подтверждение

**Флоу 6 — Спор:** История → Детали → Открыть спор → Доказательства → Решение → [Апелляция 7 дней] / Закрытие

# 2. ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ

## 2.1 Регистрация и аутентификация

**FR-001: Регистрация клиента.**
Новый пользователь создаёт аккаунт через email или номер телефона. Система отправляет код подтверждения (OTP) на указанный контакт. После ввода верного кода аккаунт считается подтверждённым, и пользователь может пользоваться платформой. Если выбран email — дополнительно требуется задать пароль. Если телефон — вход через OTP при каждом сеансе (или с сохранённой сессией).

**FR-003: Заполнение профиля.**
После регистрации пользователь заполняет профиль. Имя — обязательное поле (отображается владельцу при бронировании). Фото профиля — опционально, но система показывает индикатор заполненности и напоминает о загрузке. Профиль можно редактировать в любой момент из личного кабинета.

**FR-004: Привязка карты.**
Клиент может привязать одну или несколько банковских карт: Visa, Mastercard, МИР (только РФ), БЕЛКАРТ (только РБ). Привязка не обязательна при регистрации — система предложит это при первой попытке оплаты. Данные карт не хранятся на серверах платформы, используются только токены платёжного провайдера.

**FR-005: Возрастное ограничение.**
При регистрации клиент обязан поставить галочку, подтверждающую, что ему исполнилось 18 лет. Без этого подтверждения завершить регистрацию невозможно. Платформа не обслуживает несовершеннолетних пользователей.

**FR-006: Автоматическое создание кошелька клиента.**
Сразу после регистрации система автоматически создаёт внутренний кошелёк с нулевым балансом. Валюта кошелька определяется регионом пользователя: BYN для Беларуси, RUB для России. Кошелёк является единой точкой для всех внутренних начислений — пополнений, возвратов, кэшбэка, бонусов, сертификатов.

**FR-007: Двухфакторная аутентификация.**
Пользователь может включить дополнительный фактор защиты: SMS-код при каждом входе или TOTP-приложение (Google Authenticator, Authy). Настраивается в разделе безопасности профиля. Система рекомендует включить 2FA после первого бронирования.

**FR-008: Управление сессиями.**
Пользователь видит список всех активных сессий (устройство, браузер, IP, дата последнего входа). Может завершить любую сессию удалённо, например, если забыл выйти на чужом устройстве. Сессия автоматически истекает через 30 дней без активности.

**FR-009: Регистрация владельца.**
Владелец регистрируется через email или телефон (аналогично клиенту). Далее запускается расширенный онбординг: (1) верификация личности — KYC, (2) подписание оферты платформы, (3) заполнение платёжных реквизитов для получения выплат. Без прохождения всех трёх шагов публикация листинга невозможна.

**FR-010: KYC владельца.**
Для физических лиц — загрузка паспорта. Для юридических лиц и ИП — загрузка учредительных документов. Верификация проходит через сервис SumSub (резерв — ручная модерация). SLA проверки — не более 24 часов. KYC действует 1 год, после чего требуется повторная верификация. Если владелец не пройдёт её в срок — все листинги блокируются, вывод средств приостанавливается до повторного прохождения.

**FR-011: Подписание оферты.**
Перед публикацией первого листинга владелец обязан акцептовать оферту платформы в электронном виде. Оферта содержит условия работы, правила, финансовые условия. Дата и факт акцепта фиксируются в системе. При обновлении оферты — повторное акцептирование.

**FR-012: Платёжные реквизиты владельца.**
Владелец указывает реквизиты для получения выплат: банковскую карту или расчётный счёт. Система поддерживает разные формы собственности: физлица, ИП, самозанятые, юридические лица — документооборот и форматы отчётности адаптируются под выбранный статус. Реквизиты можно обновить в любой момент через настройки.

**FR-013: Автоматическое создание кошелька владельца.**
При завершении регистрации владельца система автоматически создаёт кошелёк с нулевым балансом в валюте его региона. Кошелёк используется для зачислений за бронирования, оплаты продвижения, подписки и вывода средств.

**FR-014: Удаление аккаунта клиента.**
Клиент может запросить удаление аккаунта через настройки профиля. Удаление происходит не мгновенно — действует льготный период 30 дней, в течение которого аккаунт можно восстановить. Система отправляет уведомления с напоминанием на 0-й, 14-й и 27-й день. При удалении: реальные средства (topup) возвращаются на исходный инструмент (карту), бонусные средства (кэшбэк, промо, рефералы, приветственный бонус) — сгорают. Персональные данные анонимизируются. Финансовая история хранится 5 лет в соответствии с законодательством.

**FR-015: Восстановление пароля.**
Пользователь нажимает «Забыл пароль» → вводит email → получает ссылку для сброса (действует 30 минут) → задаёт новый пароль → все активные сессии автоматически завершаются (принудительный logout). Для защиты от перебора — не более 3 запросов сброса за 15 минут с одного аккаунта.

**FR-016: Приветственный онбординг клиента.**
После первого входа новый клиент видит серию подсказок (onboarding tour): как искать, как бронировать, что такое кошелёк. Система предлагает рекомендации по геолокации — ближайшие популярные объекты. На кошелёк начисляется приветственный бонус: 500 ₽ (РФ) / 15 BYN (РБ) со сроком жизни 30 дней. В профиле отображается индикатор заполненности с призывами дополнить информацию.

**FR-017: Смена региона.**
Пользователь может сменить регион (BY ↔ RU) в настройках. Смена блокируется, если на аккаунте есть: ненулевой баланс кошелька, неактивированные сертификаты, активные бронирования или открытые споры. При балансе = 0 и отсутствии блокирующих условий — система создаёт новый кошелёк в новой валюте. Старый кошелёк архивируется. Статус лояльности обнуляется — начинается заново с Бронзы.

## 2.2 Листинг объектов

**FR-018: Создание карточки — базовые атрибуты.**
Владелец заполняет основную информацию об объекте: название (будет отображаться в каталоге и поиске), точный адрес (с привязкой к карте), тип объекта (из справочника: русская баня, финская сауна, хамам, спа-комплекс и т.д.), текстовое описание объёмом от 100 до 5 000 символов (описание атмосферы, особенностей, что входит в аренду).

**FR-019: Вместимость.**
Владелец указывает минимальное и максимальное количество гостей. Минимум — 1, максимум — 50 человек. Эти значения используются в фильтрах поиска, а также при валидации бронирования — система не позволит забронировать объект, если указанное число гостей превышает максимальную вместимость.

**FR-020: Удобства.**
Владелец выбирает доступные удобства из справочника платформы (мультивыбор): бассейн, купель, веники, парогенератор, комната отдыха, Wi-Fi, мангал, парковка, кондиционер и т.д. Справочник поддерживается и расширяется администрацией. Удобства отображаются иконками на карточке объекта и доступны в фильтрах поиска.

**FR-021: Правила посещения.**
Владелец задаёт правила для своего объекта: минимальный возраст посетителей (не менее 18 лет — это ограничение платформы), разрешён ли алкоголь, допускаются ли животные, разрешено ли курение. Правила отображаются клиенту на карточке объекта перед бронированием — клиент обязан ознакомиться с ними.

**FR-022: Политика отмены.**
Владелец выбирает одну из трёх предустановленных политик отмены для своего объекта:
- **Гибкая:** полный возврат (100%) при отмене за 24 часа и более до начала сеанса. При отмене менее чем за 24 часа — возврат 50%.
- **Умеренная:** 100% возврат за 72+ часа, 50% за 24–72 часа, 0% при отмене менее чем за 24 часа.
- **Строгая:** 100% за 7+ дней, 50% за 3–7 дней, 0% менее чем за 3 дня.

Политика отображается клиенту на этапе оформления и на карточке объекта.

**FR-023: Фотографии.**
Владелец загружает от 3 до 30 фотографий объекта. Минимальное разрешение — 1024×768 px. Допустимые форматы — JPEG, PNG, WebP. Максимальный размер одного файла — 10 МБ. Система автоматически генерирует 4 размера (thumbnail, medium, large, full), конвертирует в WebP для экономии трафика, создаёт blur-hash (размытое превью для быстрой загрузки) и раздаёт через CDN. Первая фотография — обложка карточки.

**FR-024: Дополнительные услуги (add-ons).**
Владелец может добавить до 20 дополнительных услуг к объекту: веники (дубовый, берёзовый), напитки, массаж, аренда полотенец, простыней, халатов и т.д. Для каждой услуги указывается название, цена и единица (за штуку, за час, за человека). Add-ons предлагаются клиенту на этапе оформления бронирования и добавляются к итоговой сумме.

**FR-025: Проверка полноты карточки.**
Перед отправкой на модерацию система проверяет заполненность карточки по чеклисту: все обязательные поля заполнены, загружено ≥ 3 фото, адрес успешно геокодирован (привязан к координатам), указана цена > 0, задано рабочее расписание. Если какие-то пункты не выполнены — карточка не отправляется, и владелец видит список того, что нужно дополнить.

**FR-026: Ручная модерация.**
Каждый новый листинг проходит проверку модератором. SLA — не более 48 часов с момента отправки. Модератор проверяет соответствие фотографий описанию, корректность адреса, отсутствие запрещённого контента. Результат — публикация или отклонение с указанием конкретной причины (владелец может исправить и отправить повторно).

**FR-027: Проверка адреса.**
Введённый адрес проходит автоматическое геокодирование (преобразование в координаты). Владелец видит точку на карте и подтверждает, что она корректна. Допустимое отклонение — не более 100 метров от реального расположения. Если точка не совпадает — владелец может перетащить маркер вручную.

**FR-028: Антифрод-проверка владельца.**
При создании листинга система автоматически проверяет владельца: поиск дубликатов аккаунтов (по телефону, email, реквизитам), проверка по стоп-листу (ранее заблокированные пользователи). Если обнаружено совпадение — листинг блокируется и передаётся на ручную проверку.

**FR-029: Редактирование с логированием.**
Владелец может редактировать карточку в любое время. Все изменения фиксируются в аудит-логе (кто, что, когда). Существенные изменения — смена адреса, смена типа объекта, замена более 50% фотографий — автоматически отправляют карточку на повторную модерацию. Незначительные изменения (описание, цена) применяются сразу.

**FR-030: Временная деактивация.**
Владелец может временно скрыть объект из поиска и каталога (отпуск, ремонт, сезонная пауза). При этом все уже подтверждённые бронирования сохраняются и выполняются. Объект просто перестаёт быть видимым для новых клиентов. Активация обратно — в один клик.

**FR-031: Полное удаление.**
Владелец может полностью удалить листинг (архивирование), но только при отсутствии активных бронирований. Если есть активные — система предлагает дождаться их завершения или отменить. Удалённый листинг перемещается в архив и не подлежит восстановлению.

**FR-032: Дублирование.**
Владелец может создать копию существующего листинга (если у него несколько похожих объектов). Копия создаётся со всеми данными, после чего владелец редактирует нужные поля (адрес, фото, название). Копия проходит модерацию как новый листинг.

**FR-033: Массовый импорт.**
Для владельцев с большим числом объектов (сети саун, банные комплексы) доступен импорт из CSV или Excel. Система предоставляет шаблон и мастер маппинга полей. Для первых 50–100 объектов в регионе предлагается ассистированный онбординг — менеджер платформы помогает заполнить карточки.

**FR-034: Пошаговый мастер (7 шагов).**
Создание первого листинга проводится через интерактивный мастер из 7 шагов:
1. **Приветствие** — видеоинструкция и обзор процесса.
2. **Информация об объекте** — название, адрес, тип, описание, вместимость, удобства, правила.
3. **Фотографии** — загрузка, сортировка, выбор обложки.
4. **Ценообразование** — базовая цена с подсказкой-рекомендацией по среднему уровню цен в районе.
5. **Расписание** — рабочие дни/часы с возможностью применить шаблон (например, «стандартная рабочая неделя»).
6. **Политика отмены** — выбор из трёх вариантов с пояснениями.
7. **Предпросмотр** — как карточка выглядит для клиента.

На каждом шаге можно сохранить черновик. Есть индикатор прогресса и навигация «назад/вперёд» между шагами.

**FR-035: Профессиональная фотосъёмка.**
Владелец может заказать профессионального фотографа через партнёрскую программу прямо из кабинета. Система показывает доступных фотографов в регионе, стоимость, примеры работ. Оплата — с кошелька владельца.

## 2.3 Поиск, фильтрация и сравнение

**FR-036: Поиск по геолокации.**
Клиент ищет объекты по своему текущему местоположению (GPS) или вводит адрес, район, город вручную. Радиус поиска — от 1 до 50 км (по умолчанию 10 км). Результаты отображаются на карте и в списке, отсортированные по удалённости. Если GPS недоступен — система предлагает выбрать город из списка.

**FR-037: Поиск по дате и времени.**
Клиент указывает дату и желаемое время. Система показывает только те объекты, у которых на эту дату/время есть свободные слоты. Учитываются буферное время между бронированиями (FR-073), минимальное время до бронирования (FR-077), максимальная дата вперёд (FR-078), а также lead time владельца.

**FR-038: Полнотекстовый поиск.**
Клиент может ввести текстовый запрос в строку поиска — название объекта, тип (например, «хамам»), ключевые слова из описания. Поиск поддерживает нечёткое совпадение (опечатки, склонения) и выдаёт релевантные результаты даже при неточных запросах.

**FR-039: Подсказки при поиске.**
По мере набора текста в строке поиска (с задержкой 300 мс) система выводит подсказки: популярные запросы, типы объектов, районы и города. Подсказки помогают клиенту быстрее найти нужное и уменьшают число пустых результатов.

**FR-040: Фильтрация.**
Клиент может сузить результаты поиска по набору фильтров:
- Тип объекта (русская баня, финская сауна, хамам и т.д.)
- Вместимость (от 1 до 50 гостей)
- Ценовой диапазон (ползунок «от–до»)
- Удобства (мультивыбор: бассейн, веники, парковка и т.д.)
- Расстояние (от 1 до 50 км)
- Минимальный рейтинг (≥ 3.0, ≥ 4.0, ≥ 4.5)
- Тип бронирования (мгновенное / по запросу)
- Статус объекта (верифицированный, Топ, Премиум)

Фильтры комбинируются логическим «И». Счётчик результатов обновляется при каждом изменении.

**FR-041: Ранжирование.**
Результаты поиска ранжируются по формуле, учитывающей несколько факторов с настраиваемыми весами:
- Релевантность запросу — 0.3
- Рейтинг объекта — 0.25
- Конверсия (отношение бронирований к просмотрам) — 0.2
- Заполняемость — 0.15
- Буст от платного продвижения — 0.1

Веса настраиваются в админ-панели и могут отличаться по регионам.

**FR-042: Ручная сортировка.**
Помимо автоматического ранжирования клиент может вручную отсортировать результаты: по цене (от низкой к высокой и наоборот), по рейтингу, по расстоянию. По умолчанию — сортировка по релевантности (FR-041).

**FR-043: Платное продвижение.**
Владельцы на тарифе «Платный» могут продвигать свои объекты: продвинутые объекты поднимаются выше в результатах поиска и помечаются значком «Рекомендуемый». На одной странице результатов отображается не более 3 продвинутых объектов, чтобы не засорять выдачу рекламой. Ставка за продвижение — аукционная, минимум 50 ₽/день.

**FR-044: Карточка объекта.**
Полная страница объекта содержит: фотогалерею (свайп/листание), описание, правила посещения, календарь с доступными слотами, **полную разбивку цены** (базовая цена, стоимость add-ons, сервисный сбор, скидки, средняя цена по району для сравнения, итого к оплате), профиль владельца (рейтинг, количество объектов, дата регистрации), блок похожих объектов (до 6 штук) и кнопку оплаты с кошелька.

**FR-045: Избранное.**
Клиент может добавить объект в избранное (кнопка «сердечко»). Максимум — 100 объектов. Список избранного доступен в личном кабинете, объекты можно удалять из него. Если избранный объект деактивирован — он остаётся в списке с пометкой «временно недоступен».

**FR-046: Сравнение.**
Клиент может выбрать 2–3 объекта и открыть их в режиме сравнения — табличный вид с параметрами бок о бок: цена, рейтинг, вместимость, удобства, расстояние, политика отмены. Помогает выбрать между похожими вариантами.

**FR-047: Поделиться карточкой.**
Клиент может отправить ссылку на объект в мессенджер, соцсеть или скопировать URL. Ссылка содержит Open Graph-метатеги (превью с фото и описанием). Поддерживаются диплинки: при наличии установленного приложения (в будущем) — откроется в приложении, иначе — в браузере.

**FR-048: Карта.**
Результаты поиска отображаются на интерактивной карте. Каждый объект — маркер с ценой. При более чем 50 маркерах в зоне видимости — включается кластеризация (маркеры группируются с числом). Доступны два слоя отображения: схема и спутник.

**FR-049: Взаимодействие с картой.**
При перемещении карты появляется кнопка «Искать в этой области» — обновляет результаты по новой видимой зоне. При клике на маркер — мини-карточка объекта (фото, название, цена, рейтинг) с кнопкой перехода на полную страницу. При наведении на объект в списке — подсвечивается соответствующий маркер на карте (и наоборот).

**FR-050: Режимы.**
Три режима отображения результатов: «Список» (вертикальная лента карточек), «Карта» (полноэкранная карта), «Сплит-вью» (список слева, карта справа). Фильтры и сортировка синхронны во всех режимах — изменение в одном автоматически обновляет остальные.

**FR-051: Недавно просмотренные.**
Система запоминает последние 20 объектов, которые клиент открывал. Блок «Недавно просмотренные» отображается на главном экране и в поиске. Помогает вернуться к объекту, который клиент уже смотрел, но не забронировал.

**FR-052: Сохранённые поиски.**
Клиент может сохранить параметры поиска (регион, даты, фильтры). Когда появляется новый объект, соответствующий сохранённым критериям — клиент получает push-уведомление. Удобно для тех, кто ищет что-то конкретное, но пока не нашёл.

**FR-053: Изохроны.**
Вместо радиуса «10 км по прямой» — отображение зон реальной транспортной доступности: «15 минут на машине», «30 минут на общественном транспорте». Помогает клиенту оценить реальное время в пути.

**FR-054: Транспортная доступность.**
Дополнительный слой на карте с информацией о транспорте: ближайшие станции метро, автобусные остановки, парковки рядом с объектом. Отображается на карточке объекта и на карте.

## 2.4 Бронирование и календарь

**FR-055: Мгновенное бронирование.**
Клиент выбирает дату, время начала и длительность сеанса, при желании добавляет дополнительные услуги (add-ons). Система показывает **полную разбивку цены** отдельными строками: базовая стоимость, стоимость каждого add-on, сервисный сбор, скидки (промокод, длительный сеанс, лояльность), итого. Клиент подтверждает → переходит к оплате → после успешной оплаты бронирование подтверждается автоматически → обе стороны (клиент и владелец) получают уведомления (push + email) с деталями.

**FR-056: Применение промокода и кошелька.**
На экране оформления клиент может ввести промокод — система валидирует его (активен, не истёк, применим к данному объекту) и пересчитывает стоимость. Также клиент может частично или полностью оплатить с кошелька: отображается текущий баланс, ползунок для выбора суммы списания, автоматически пересчитывается остаток к оплате картой.

**FR-057: Выбор источника оплаты.**
Клиент выбирает способ оплаты:
- Полностью с кошелька (если баланс достаточен)
- Полностью картой / СБП / Apple Pay / Google Pay
- Комбинированная оплата (часть с кошелька + часть картой)

Система чётко показывает, сколько будет списано с каждого источника.

**FR-058: Бронирование по запросу.**
Для объектов, где владелец включил режим «по запросу» (вместо мгновенного), процесс отличается: клиент оформляет заявку → система блокирует (холдирует) средства на карте или кошельке → владелец получает push + email + SMS с деталями запроса → у владельца есть 24 часа (настраивается) на ответ → при одобрении: средства списываются, бронирование подтверждается → при отклонении: холд снимается, средства возвращаются, клиент получает уведомление. Если владелец не ответил за 24 часа — запрос автоматически отклоняется.

**FR-059: Повторное бронирование.**
В истории бронирований рядом с завершённым бронированием отображается кнопка «Забронировать снова». При нажатии — форма оформления предзаполняется данными из прошлого визита (дата не копируется, остальное — время, длительность, add-ons — подставляется). Цена пересчитывается по текущим тарифам объекта.

**FR-061: Конкурентный контроль.**
Если два клиента одновременно пытаются забронировать один и тот же слот, система отклоняет второго и показывает сообщение: «Этот слот только что занят. Ближайшие свободные: ...» — с предложением выбрать альтернативное время. Это исключает двойные бронирования.

**FR-062: Просмотр деталей.**
Клиент и владелец видят полные детали бронирования: объект, дата/время, длительность, количество гостей, add-ons, полная разбивка цены, статус, контакты второй стороны (после оплаты), адрес с картой, кнопки действий (отмена, изменение, продление, сообщение).

**FR-063: Мессенджер.**
Клиент и владелец могут обмениваться сообщениями в привязке к конкретному бронированию. Мессенджер доступен только после оплаты (или подтверждения запроса). Система автоматически фильтрует сообщения: номера телефонов, email-адреса, URL — блокируются, чтобы сделка оставалась на платформе. Сообщения сохраняются и могут быть использованы при споре.

**FR-064: Напоминания.**
Клиент получает автоматические напоминания о предстоящем визите: за 24 часа (push + email) и за 2 часа (push). Интервалы настраиваются владельцем. Если push недоступен — резервный канал SMS. Напоминание содержит адрес, время, кнопку для построения маршрута.

**FR-065: Продление.**
Если следующий слот после текущего бронирования свободен, клиент может продлить сеанс прямо во время визита. Доплата рассчитывается по текущему тарифу объекта. Продление подтверждается обеими сторонами.

**FR-066: Фиксация прибытия/убытия.**
Владелец нажимает кнопку «Гость прибыл» при появлении клиента и «Гость ушёл» по окончании. За 5 минут до начала сеанса — push-напоминание владельцу отметить прибытие. Фиксация необходима для определения неявок (no-show) и корректного расчёта периода претензий.

**FR-067: Изменение бронирования.**
Клиент может изменить бронирование не более 3 раз: сменить дату/время, длительность, add-ons. Система пересчитывает стоимость: если новая сумма больше — клиент доплачивает разницу; если меньше — разница возвращается (пропорционально источникам оплаты); если равна — просто обновляется слот. Изменение требует подтверждения обеих сторон.

**FR-068: Отмена бронирования.**
Клиент может отменить бронирование из раздела «История». Сумма возврата рассчитывается по политике отмены объекта (FR-022). Клиент выбирает способ возврата: на кошелёк (мгновенно) или на карту (3–10 рабочих дней). Если оплата была комбинированной — возврат пропорционально каждому источнику. **Бонус за возврат на кошелёк: +5%** от суммы возврата (настраивается от 0 до 15%) — стимулирует оставлять деньги на платформе.

**FR-069: Штраф владельцу за отмену.**
Если владелец отменяет подтверждённое бронирование — клиент получает компенсацию 10% от стоимости на кошелёк (за счёт платформы). Система считает отмены: > 3 отмен за 30 дней — предупреждение владельцу, > 5 — автоматическая деактивация всех листингов до разбирательства.

**FR-070: Неявка (no-show).**
Если клиент не пришёл и владелец не зафиксировал прибытие — начинается льготный период 30 минут. После его истечения бронирование считается неявкой. Средства удерживаются по политике отмены. Клиент может оспорить неявку в течение 2 часов, приложив доказательства (GPS-координаты в радиусе 200 м от объекта). Если у владельца > 20% неявок (клиенты оспорили) — предупреждение о возможных проблемах с описанием объекта.

**FR-071: Рабочее расписание.**
Владелец задаёт расписание работы объекта: выбирает рабочие дни недели, для каждого дня — время начала и окончания работы. Шаг — 30 минут (например, с 10:00 до 22:00). На основании расписания система автоматически генерирует доступные слоты для бронирования.

**FR-072: Ручная блокировка слотов.**
Владелец может заблокировать конкретные слоты (даты/время), когда объект недоступен: ремонт, личное использование, форс-мажор. При блокировке указывается причина (для аудита). Заблокированные слоты не отображаются клиентам.

**FR-073: Буферное время.**
Между двумя последовательными бронированиями автоматически вставляется буферное время — по умолчанию 30 минут (настраивается от 0 до 120 минут, шаг 15 минут). Буфер нужен для уборки и подготовки. В это время объект недоступен для бронирования.

**FR-074: Синхронизация с внешними календарями.**
Владелец может подключить внешний календарь (iCal, Google Calendar, Яндекс.Календарь). Система синхронизируется каждые 15 минут: события из внешнего календаря блокируют соответствующие слоты в RelaxHub, и наоборот — бронирования из RelaxHub создают события во внешнем календаре.

**FR-075: Автообновление доступности.**
При создании, изменении или отмене любого бронирования доступность объекта обновляется в реальном времени — менее 1 секунды. Это гарантирует, что клиенты всегда видят актуальные слоты и исключает ситуации двойного бронирования.

**FR-076: Визуальный календарь.**
Владелец видит календарь своих бронирований в трёх режимах: день (почасовая сетка), неделя, месяц. Бронирования цветово кодированы по статусу: подтверждённые (зелёный), ожидающие (жёлтый), отменённые (красный), заблокированные (серый). Для владельцев с несколькими объектами — сводный вид всех объектов на одном экране.

**FR-077: Минимальное время до бронирования.**
Владелец задаёт минимальный промежуток между текущим моментом и началом бронирования. По умолчанию — 2 часа (настраивается от 0 до 48 часов). Например, если lead time = 2 ч, а сейчас 15:00 — ближайший доступный слот начинается не раньше 17:00. Это даёт владельцу время подготовиться.

**FR-078: Максимальная дата вперёд.**
Владелец задаёт, насколько далеко вперёд можно бронировать. По умолчанию — 90 дней (настраивается от 7 до 365). Слоты за пределами этого окна не отображаются клиентам.

**FR-079: Мониторинг процента ответов.**
Система отслеживает, как быстро и часто владелец отвечает на запросы бронирования. Если процент ответов < 50% — предупреждение. Если < 30% за 60 дней — система принудительно переводит объект в режим мгновенного бронирования (без подтверждения владельца) или деактивирует листинг до выяснения.

**FR-080: Режим форс-мажора.**
Администратор платформы может активировать режим форс-мажора для конкретного региона и диапазона дат (например, стихийное бедствие, ЧС). При активации: все бронирования в указанном регионе и датах автоматически отменяются, клиенты получают 100% возврат, владельцы и клиенты уведомляются.

**FR-081: Поделиться бронированием.**
Клиент может сгенерировать ссылку на своё бронирование и отправить друзьям. Ссылка содержит предзаполненные дату и объект — получатель может сразу забронировать тот же объект на ту же дату (если есть свободные слоты).

## 2.5 Ценообразование

**FR-082: Базовая цена.**
Владелец устанавливает базовую стоимость аренды — за час или за сеанс (фиксированный блок времени). Минимальная цена: 100 ₽ (РФ) / 3 BYN (РБ). Максимальная: 100 000 ₽ / 3 000 BYN. Цена отображается клиенту до оформления и включается в итоговую разбивку.

**FR-083: Минимальная длительность.**
Владелец задаёт минимальную длительность бронирования. По умолчанию — 2 часа (настраивается от 1 до 8 часов, шаг 0.5 часа). Клиент не сможет забронировать объект на время меньше минимальной длительности.

**FR-084: Скидка за длительный сеанс.**
Владелец может настроить автоматическую скидку для длительных бронирований: например, −10% при бронировании на 3 и более часов. Порог и процент настраиваются. Скидка применяется автоматически и отображается в разбивке цены.

**FR-085: Доплата за гостей.**
Если количество гостей превышает базовую вместимость — владелец может задать фиксированную доплату за каждого дополнительного гостя. Например, базовая вместимость 6 человек, доплата 500 ₽ за каждого 7-го и далее.

**FR-086: Цены по дням недели.**
Владелец может установить разные цены для будних и выходных дней, или индивидуально для каждого дня недели. Например: пн–чт — 2 000 ₽/ч, пт — 2 500 ₽/ч, сб–вс — 3 000 ₽/ч. Калькулятор при бронировании автоматически подставляет цену по дню недели.

**FR-087: Сезонные тарифы.**
Владелец может задать сезонные надбавки или скидки для диапазонов дат: например, с 1 июня по 31 августа — летний тариф, с 20 декабря по 10 января — праздничный тариф. Указывается диапазон дат и скорректированная цена.

**FR-088: Праздничные цены.**
Администратор платформы ведёт справочник праздников по регионам (Новый год, 8 Марта, 23 Февраля и т.д.). Владелец задаёт множитель для праздничных дней: от 1.0 (без наценки) до 2.0 (двойная цена). Клиент видит пометку «праздничная цена» при бронировании.

**FR-089: Умное ценообразование (Smart Pricing).**
Система рекомендует владельцу оптимальную цену на основании анализа: текущей загрузки, спроса в районе, цен конкурентов. Рекомендуемый коэффициент — от 0.8 (снижение на 20%) до 1.5 (повышение на 50%). Владелец видит рекомендацию, но может отклонить или отключить функцию полностью.

**FR-090: Скидки «в последний момент».**
Если слот не забронирован и до его начала осталось менее 6 часов (настраивается), система может автоматически применить скидку. По умолчанию — 20%. Владелец задаёт процент и порог времени, может отключить. Объекты со скидкой помечаются значком «Last minute» в поиске.

**FR-091: Страховой депозит.**
Владелец может установить страховой залог: по умолчанию 0 (не взимается), максимум — 50% от базовой цены. Залог блокируется на карте клиента перед визитом. Если претензий нет — автоматически возвращается через 48 часов после визита. В случае ущерба — владелец открывает спор.

## 2.6 Платежи, кошелёк и финансы

### Приём платежей

**FR-092: Методы оплаты.**
Поддерживаемые способы оплаты зависят от региона:
- **РФ:** Visa, Mastercard, МИР, СБП (система быстрых платежей), Apple Pay, Google Pay, кошелёк RelaxHub.
- **РБ:** Visa, Mastercard, БЕЛКАРТ, ЕРИП, кошелёк RelaxHub.

Клиент выбирает способ оплаты на экране оформления. Карты сохраняются в виде токенов для быстрых повторных платежей.

**FR-093: Комбо-оплата.**
Клиент может оплатить бронирование частично с кошелька, а остаток — картой или через СБП. Если списание с карты не прошло (ошибка, недостаток средств) — уже списанные средства с кошелька автоматически возвращаются обратно на кошелёк. Транзакция атомарна: либо проходит целиком, либо откатывается полностью.

**FR-094: Авторизация и холд.**
Для бронирований «по запросу» (FR-058) система блокирует (холдирует) средства на карте клиента или на его кошельке на срок до 72 часов. Деньги не списываются, но недоступны для клиента. Если владелец одобрит — холд конвертируется в оплату. Если отклонит или истечёт таймаут — холд снимается.

**FR-095: Фискализация.**
При каждой финансовой операции система автоматически формирует фискальный чек через подключённого оператора фискальных данных (АТОЛ Онлайн в РФ, провайдер РБ). Поддерживаемые типы чеков: «аванс» (при холде), «зачёт аванса» (при подтверждении), «полная оплата» (при мгновенном бронировании), «возврат» (при отмене). Чек отправляется клиенту на email.

**FR-096: Обработка ошибок оплаты.**
При ошибке оплаты клиент видит понятное сообщение на русском языке (не технический код): «Недостаточно средств», «Карта заблокирована», «Попробуйте другую карту» и т.д. Для временных ошибок (таймаут сети) — система автоматически повторяет попытку до 3 раз с нарастающей задержкой: 2, 4, 8 секунд. При постоянной ошибке — предложение использовать другой способ оплаты.

### Комиссии и сборы

**FR-097: Сервисный сбор.**
С каждого бронирования платформа взимает сервисный сбор с клиента. По умолчанию — 10% от стоимости сеанса (без add-ons). Диапазон: от 0 до 25%, шаг 0.5%. Сбор может быть разным для разных регионов и категорий объектов. Настраивается в админ-панели. Сбор показывается клиенту отдельной строкой в разбивке цены.

**FR-098: Модель с владельцев.**
Комиссия с владельцев = 0% на всех тарифах. Платформа не берёт процент от бронирований. Монетизация со стороны владельцев — через подписку «Платный» (фиксированная ежемесячная плата за расширенные функции).

**FR-099: Промокоды.**
Промокод может быть создан платформой (за счёт сервисного сбора) или владельцем (за свой счёт). Типы скидок: фиксированная сумма (−500 ₽), процент (−15%), бесплатный add-on. У промокода есть срок действия, лимит использований, привязка к региону/категории/объекту.

### Выплаты владельцам

**FR-100: Зачисление на кошелёк владельца.**
После завершения визита и истечения периода претензий (по умолчанию 48 часов, настраивается от 24 до 168 часов) — полная сумма бронирования (без вычета комиссии, т.к. комиссия = 0%) зачисляется на кошелёк владельца. До этого средства находятся на эскроу-счёте платформы.

**FR-101: Вывод средств.**
Владелец выводит деньги с кошелька на банковскую карту или расчётный счёт. Скорость: мгновенно (через СБП в РФ) или 1–3 рабочих дня (банковский перевод). Минимальная сумма вывода: 500 ₽ / 15 BYN. Лимиты для физических лиц: 500 000 ₽ в сутки, 3 000 000 ₽ в месяц. Для юрлиц лимиты настраиваются индивидуально.

**FR-102: Автовывод.**
Владелец может настроить автоматический вывод средств при достижении порога баланса (например, «выводить всё при балансе > 10 000 ₽»). По умолчанию — отключён. Настраивается в личном кабинете.

**FR-103: Удержание депозита.**
Страховой депозит клиента (FR-091) удерживается на эскроу-счёте платформы до окончания периода претензий. Если владелец не подал жалобу — депозит автоматически возвращается клиенту. Если подал — средства замораживаются до рассмотрения спора.

**FR-104: Акты и отчёты.**
Платформа автоматически формирует финансовые документы для владельцев: акты оказанных услуг, отчёты по выплатам. Форматы: PDF для всех, XML (формат 1С) — для юридических лиц и ИП. Документы доступны для скачивания в разделе «Финансы» личного кабинета.

**FR-105: Налоговый статус.**
Владелец указывает свой налоговый статус при регистрации: ИП, самозанятый, физлицо, юридическое лицо. Система адаптирует документооборот, формы отчётности и схему фискализации под выбранный статус. Статус можно изменить в настройках.

### Возвраты

**FR-106: Автоматический возврат.**
При отмене бронирования сумма возврата рассчитывается по политике отмены объекта (FR-022). Возврат направляется: на кошелёк (мгновенно, в течение нескольких секунд) или на исходный платёжный инструмент — карту/СБП (3–10 рабочих дней, зависит от банка). При комбинированной оплате — возврат пропорционально каждому источнику.

**FR-107: Бонус за возврат на кошелёк.**
Если клиент выбирает возврат на кошелёк (а не на карту), система начисляет бонус: +5% от суммы возврата (настраивается от 0 до 15% в админ-панели). Пример: возврат 2 000 ₽ на кошелёк → на кошелёк поступает 2 100 ₽. Это стимулирует клиента оставлять деньги на платформе.

**FR-108: Возврат комбо.**
Если бронирование оплачивалось комбинированно (часть с кошелька + часть картой), возврат происходит пропорционально: та доля, что была оплачена с кошелька — возвращается на кошелёк; та, что картой — на карту. Бонус +5% применяется только к части, возвращённой на кошелёк.

**FR-109: Ручной возврат.**
В спорных или нестандартных ситуациях оператор поддержки уровня L2 и выше может оформить ручной возврат: частичный или полный, на кошелёк или на карту. Каждый ручной возврат сопровождается обязательным комментарием с причиной и фиксируется в аудит-логе.

### Кошелёк клиента

**FR-110: Пополнение.**
Клиент может пополнить кошелёк с банковской карты или через СБП/ЕРИП. Минимальная сумма одного пополнения: 500 ₽ / 15 BYN. Максимальная сумма одного пополнения: 30 000 ₽ / 900 BYN. Максимальный баланс кошелька: 100 000 ₽ / 3 000 BYN. При попытке превысить лимит — система показывает ошибку с пояснением.

**FR-111: Источники зачислений.**
На кошелёк клиента могут поступать средства из разных источников, каждый из которых тегируется в системе:
- **topup** — пополнение с карты (реальные средства)
- **refund** — возврат за отменённое бронирование
- **compensation** — компенсация от платформы
- **promo** — промоакция
- **cashback** — кэшбэк по программе лояльности
- **gift_cert** — активированный подарочный сертификат
- **referral** — бонус за приглашённого друга
- **welcome_bonus** — приветственный бонус при регистрации

Тегирование необходимо для правильного расчёта сгорания, приоритетов списания и возвратов при удалении аккаунта.

**FR-112: Списание.**
Средства с кошелька списываются при оплате бронирований, дополнительных услуг (add-ons), продлений сеанса и подписки «Банный клуб». Приоритет списания: сначала бонусные средства с ближайшим сроком сгорания (чтобы не пропали), затем бессрочные средства в порядке FIFO (первым пришёл — первым списался).

**FR-113: Холдирование.**
При бронировании «по запросу» средства на кошельке блокируются (холд). Заблокированные средства видны в балансе с пометкой «заморожено» и не могут быть использованы для других операций. После одобрения — списываются; после отклонения — размораживаются.

**FR-114: Запрет вывода.**
Кошелёк клиента предназначен только для внутренних операций платформы. Вывести средства с кошелька клиента на карту или банковский счёт невозможно. Исключение — удаление аккаунта (FR-014), при котором реальные средства (topup) возвращаются на исходный инструмент.

**FR-115: История операций.**
Клиент видит полный лог всех операций кошелька: пополнения, списания, возвраты, начисления бонусов, сгорания. По каждой записи: дата, сумма, тип, описание, связанное бронирование. Доступна фильтрация по типу и дате. Экспорт в CSV и PDF.

**FR-116: Единый баланс.**
Клиент видит одну итоговую цифру баланса (без разделения на «реальные» и «бонусные»). Разделение по тегам существует только в базе данных для внутренней логики (приоритет списания, сгорание, возвраты). Это упрощает пользовательский опыт.

### Кошелёк владельца

**FR-117: Источники зачислений.**
На кошелёк владельца поступают: выплаты за завершённые бронирования (после периода претензий), компенсации от платформы, ручные начисления администратора. Каждое зачисление тегируется и привязано к конкретному бронированию или операции.

**FR-118: Списания.**
С кошелька владельца списываются: вывод средств на карту/счёт, оплата платного продвижения, оплата подписки «Платный», оплата дополнительных сервисов (профессиональная фотосъёмка и т.д.), штрафы (за отмену бронирования, нарушения).

**FR-119: Холдирование.**
Средства на кошельке владельца могут быть заморожены: в течение периода претензий (48 ч после визита), при открытом споре по бронированию. Замороженные средства видны в балансе, но недоступны для вывода.

**FR-120: История операций.**
Полный лог всех операций: зачисления, списания, заморозки, разморозки. Фильтрация по типу, дате, объекту. Экспорт в CSV и PDF. Интеграция с разделом «Финансы» в личном кабинете.

### Сгорание бонусов

**FR-121: Правила.**
Бонусные средства имеют ограниченный срок жизни:
- **promo, cashback, referral, welcome_bonus** — по умолчанию 180 дней (настраивается: 90 / 180 / 365 дней).
- **topup, refund, gift_cert** — бессрочно (не сгорают).

Срок считается от момента начисления каждой конкретной транзакции.

**FR-122: Уведомления о сгорании.**
Клиент получает предупреждение о скором сгорании бонусов: за 14 дней (push + email) и за 3 дня (push + email). Уведомление содержит сумму, которая сгорит, и предложение использовать её для бронирования.

**FR-123: Автоматическое списание.**
Ежедневно (ночью) система автоматически списывает все бонусные средства, у которых истёк срок жизни. Операция фиксируется в истории кошелька с типом «сгорание».

### Финансовая отчётность

**FR-124: Эскроу.**
Все средства от клиентов поступают на транзитный (эскроу) счёт платформы, а не напрямую владельцу. Средства удерживаются до момента: визит завершён + период претензий (48 ч) истёк + споров нет. Только после этого — перевод на кошелёк владельца.

**FR-125: Сверка транзакций.**
Ежедневно система автоматически сверяет внутренний реестр транзакций с данными платёжного провайдера. Допустимое расхождение — 0 (нулевое). При любом расхождении — автоматический алерт финансисту с деталями.

**FR-126: Учёт обязательств.**
Балансы кошельков клиентов учитываются как обязательства платформы (деньги, которые платформа «должна» клиентам). Балансы кошельков владельцев — как заработанные, но не выведенные средства. Эти данные отражаются в финансовой отчётности платформы.

**FR-127: Float-мониторинг.**
Ежедневно система формирует снимок: суммарный баланс кошельков клиентов + суммарный баланс кошельков владельцев + средства на эскроу + остаток на банковском счёте платформы. Расхождение (float drift) → автоматический алерт финансисту. Float-данные отображаются на дашборде в админ-панели.

**FR-128: Банковская реконсиляция.**
Система импортирует банковскую выписку и автоматически сопоставляет каждую строку с внутренними транзакциями. Несопоставленные записи → в очередь финансисту (SLA рассмотрения — ≤ 24 часа).

## 2.7 Отзывы и рейтинги

**FR-129: Автоматический запрос отзыва.**
Через 2 часа после фиксации убытия (настраивается: от 2 до 24 часов) клиент получает push + email с просьбой оставить отзыв. Сообщение содержит ссылку на форму отзыва с предзаполненными данными бронирования.

**FR-130: Запрос оценки клиента от владельца.**
Одновременно с запросом отзыва от клиента (FR-129) владелец получает аналогичный запрос — оценить клиента: пунктуальность, чистота после визита, соблюдение правил. Двусторонняя система позволяет обеим сторонам строить репутацию.

**FR-131: Двусторонняя система.**
И клиент, и владелец оставляют отзывы независимо друг от друга, не видя чужой отзыв. Раскрытие (оба отзыва становятся видимы) происходит при наступлении одного из двух условий: (1) оба опубликовали свой отзыв; (2) прошло 14 дней с момента визита. До раскрытия — можно редактировать свой отзыв. После — изменения возможны только через обращение к модератору.

**FR-132: Многокритериальная оценка.**
Клиент оценивает объект по нескольким критериям: чистота, соответствие описанию, общение с владельцем, соотношение цена/качество. Шкала — от 1 до 5 с шагом 0.5. Итоговый рейтинг объекта — среднее по всем критериям. Текстовый комментарий — опционален, но система поощряет его написание (индикатор полноты).

**FR-133: Автомодерация.**
Перед публикацией каждый отзыв проходит NLP-анализ: проверка на токсичность (оскорбления, нецензурная лексика), спам (повторяющийся текст, ссылки), подозрение на фейк (очень похожие отзывы от разных аккаунтов). Подозрительные отзывы попадают в очередь модератору, а не публикуются сразу.

**FR-134: Ручная модерация.**
Модератор рассматривает отзыв с полным контекстом: данные бронирования, переписка мессенджера, история взаимодействий. Возможные действия: одобрить (опубликовать), удалить (с указанием причины), отредактировать (убрать нецензурные фрагменты, сохранив суть).

**FR-135: Ответ владельца.**
Владелец может оставить один публичный ответ на каждый отзыв. Ответ отображается под отзывом клиента и виден всем. Повторные ответы невозможны (один ответ — окончательный). Ответ также проходит модерацию.

**FR-136: Рейтинг (Bayesian average).**
Числовой рейтинг объекта отображается при наличии ≥ 3 отзывов. Рассчитывается по методу Bayesian average (учитывает не только среднее, но и количество оценок — объект с 5.0 и 3 отзывами не превосходит объект с 4.8 и 50 отзывами). Пересчёт происходит при каждом новом или изменённом отзыве.

**FR-137: Мониторинг качества.**
Система отслеживает рейтинг объектов: если рейтинг опускается ниже 3.0 — владелец получает предупреждение с рекомендациями по улучшению. Если ниже 2.0 — объект автоматически снимается с публикации (депубликуется) до улучшения ситуации.

**FR-138: Статусы объектов.**
Объекты могут получить визуальные статусы-бейджи:
- **Верифицированный** — прошёл модерацию (все объекты).
- **Топ** — рейтинг ≥ 4.5 и ≥ 10 отзывов.
- **Премиум** — владелец оплатил продвижение.

Статусы отображаются на карточке в поиске и привлекают больше внимания клиентов.

**FR-138a–138d: Детализация.**
Подробное описание жизненного цикла отзыва: состояния до и после раскрытия, удаление отзыва (автором или модератором), подача жалобы на отзыв, влияние удалённых/отклонённых отзывов на общий рейтинг.

## 2.8 Уведомления

**FR-139: Системные уведомления.**
Платформа отправляет уведомления по следующим событиям:

| Событие | Получатель | Каналы |
|---------|-----------|--------|
| Подтверждение бронирования | Клиент + Владелец | push + email |
| Напоминание 24ч / 2ч | Клиент | push + email / push |
| Отмена / Изменение | Оба | push + email |
| Новый запрос на бронирование | Владелец | push + email + SMS |
| Таймаут запроса (24 ч истекли) | Оба | push + email |
| Новый отзыв | Владелец | push + email |
| Новое сообщение в мессенджере | Адресат | push |
| Зачисление на кошелёк | Пользователь | push |
| Сгорание бонусов (за 14д / 3д) | Клиент | push + email |
| Решение по спору | Оба | push + email |
| Неявка (no-show) | Клиент | push + email |
| Листинг одобрён/отклонён | Владелец | push + email |
| Предупреждение о низком рейтинге | Владелец | push + email |
| KYC истекает | Владелец | push + email |
| Подписка: продление / неоплата | Владелец | push + email |
| Продвижение: бюджет исчерпан / пауза | Владелец | push |
| Бронирование/отмена (для сотрудника) | Сотрудник владельца | push + email |

**FR-140: Каналы.**
Три канала доставки:
1. **Push-уведомления** — через Firebase Cloud Messaging (FCM) и APNs. Основной канал — мгновенная доставка.
2. **Email** — дублирование важных событий, детальная информация.
3. **SMS** — резервный канал, используется, если push не доставлен в течение заданного времени.

Приоритетная цепочка: push → если не доставлен за N минут → email → если критично → SMS.

**FR-141: Управление.**
Клиент и владелец могут настроить уведомления: включить/отключить по типу события и по каналу. Пример: «Хочу push о новых бронированиях, но не хочу email». Исключение — некоторые уведомления нельзя отключить: подтверждение бронирования, решение по спору.

**FR-142: Запрос push.**
Запрос разрешения на push-уведомления отображается не при регистрации (когда пользователь ещё не вовлечён), а после первого бронирования — когда push становится по-настоящему полезен. Это увеличивает конверсию согласия.

## 2.9 Модерация контента

**FR-143: Очередь модерации листингов.**
Все новые листинги и листинги после существенных изменений (FR-029) попадают в очередь модерации. Очередь сортируется по приоритету: новые владельцы (первый листинг) — в первую очередь; повторные публикации — во вторую.

**FR-144: Инструменты модератора.**
Модератор видит: полные данные листинга, фото, адрес на карте, информацию о владельце. Доступные действия: одобрить публикацию, отклонить с указанием причины, деактивировать (если нарушения обнаружены после публикации), массовые операции (одобрить/отклонить несколько за раз).

**FR-145: Очередь модерации отзывов.**
Отзывы, помеченные автомодерацией (FR-133), попадают в отдельную очередь. Модератор видит: текст отзыва, детали бронирования, переписку сторон, результат NLP-анализа (почему отзыв был помечен). Решение: опубликовать, удалить, отредактировать.

**FR-146: Дашборд модерации.**
Общий экран для руководителя модерации: размер очереди, среднее время ожидания, соблюдение SLA, распределение нагрузки между модераторами. Помогает управлять процессом и выявлять узкие места.

## 2.10 Аналитика

### Платформа

**FR-147: Воронки конверсии.**
Визуализация пользовательской воронки: посещение сайта → поиск → просмотр карточки → начало оформления → оплата → завершённый визит. На каждом шаге — количество пользователей и процент конверсии. Фильтрация по региону, периоду, типу объекта.

**FR-148: Метрики предложения.**
Дашборд с ключевыми показателями стороны предложения: количество активных листингов, средняя заполняемость (% занятых слотов), ADR (средняя стоимость бронирования), новые/деактивированные листинги по периодам.

**FR-149: Метрики спроса.**
DAU/MAU (дневные/месячные активные пользователи), CAC (стоимость привлечения клиента), LTV (пожизненная ценность клиента), churn (отток — % клиентов, не вернувшихся за 90 дней).

**FR-150: Финансовые KPI.**
GMV (общий оборот бронирований), Take Rate (доля дохода платформы от GMV), Revenue (доход платформы: сбор + подписки + продвижение), EBITDA.

**FR-151: Метрики кошелька.**
Суммарный баланс кошельков, доля бронирований, оплаченных с кошелька (%), объём сгоревших бонусов, средний баланс на пользователя.

**FR-152: Float в дашборде.**
Текущий float (кошельки + эскроу) отображается на финансовом дашборде админ-панели в реальном времени.

**FR-153: Географическая карта спроса/предложения.**
Тепловая карта: где больше объектов (предложение) и где больше запросов (спрос). Помогает выявлять дефицитные зоны — районы с высоким спросом и малым числом объектов.

**FR-154: Когортный анализ.**
Разбивка пользователей по когортам (месяц регистрации) и отслеживание их поведения во времени: удержание, частота бронирований, средний чек. Позволяет оценить качество привлечения и эффект маркетинговых акций.

### Для владельцев

Дашборд в личном кабинете: загруженность объектов (% занятых слотов по периодам), динамика дохода (график за неделю/месяц/год), количество просмотров карточки, конверсия (просмотры → бронирования), текущий баланс кошелька, анонимное сравнение с конкурентами в районе (средняя цена, заполняемость, рейтинг), CRM-аналитика (количество уникальных гостей, repeat rate — доля повторных визитов, LTV клиентов).

### Операционная

Поддержка: CSAT (удовлетворённость клиентов после обращения), FCR (решение с первого обращения), AHT (среднее время обработки тикета), SLA (% обращений, закрытых вовремя). P&L (прибыль и убытки платформы), unit-экономика (доход/расход на одно бронирование), отчёт по обязательствам (кошельки, эскроу).

## 2.11 Поддержка и споры

**FR-155: Поддержка.**
Мультиканальный вход (чат в приложении, email, форма на сайте) → все обращения попадают в единую очередь. Каждое обращение классифицируется: вопрос (как сделать?), проблема (не работает), жалоба (качество объекта), запрос на возврат. Три уровня обработки:
- **L1 — бот:** автоматические ответы на типовые вопросы. SLA — менее 5 минут.
- **L2 — оператор:** ручная обработка, доступ к деталям бронирования, переписке, кошельку. SLA — менее 2 часов.
- **L3 — медиатор:** рассмотрение сложных случаев и споров. SLA — менее 24 часов.

Эскалация между уровнями — автоматическая (по типу обращения или при неспособности предыдущего уровня решить). После закрытия тикета — запрос CSAT (оценка удовлетворённости).

**Споры:**
Клиент или владелец открывает спор (претензию) по конкретному бронированию. Обе стороны предоставляют доказательства: фото, скриншоты, GPS-данные, переписку — в течение 72 часов. Медиатор рассматривает дело (SLA — 48 часов) и выносит решение: полный/частичный возврат клиенту, отказ в претензии, компенсация. Проигравшая сторона может подать апелляцию в течение 7 дней — рассматривает старший медиатор.

## 2.12 CRM для владельцев

**Карточка гостя:**
Создаётся автоматически при первом бронировании гостя у конкретного владельца. Содержит: контактные данные (имя, аватар), полную историю визитов к этому владельцу, предпочтения (любимые add-ons, время посещения), средний чек, LTV (суммарная выручка от этого гостя), заметки владельца (свободный текст), теги (VIP, проблемный, корпоративный и т.д.).

**База:**
Полный список всех гостей владельца с поиском по имени, фильтрацией по тегам, дате последнего визита, LTV. Экспорт базы в CSV.

**Сегментация:**
Предустановленные сегменты: «Новые» (1 визит), «Постоянные» (3+ визита), «Потерянные» (нет визитов > 90 дней), «VIP» (LTV > порога). Конструктор кастомных сегментов: по количеству визитов, среднему чеку, дате последнего визита, тегам. RFM-анализ (Recency-Frequency-Monetary) — для глубокой сегментации.

**Рассылки:**
Владелец создаёт рассылку: текст + изображение, выбирает целевой сегмент, может добавить персонализацию (имя гостя, дата последнего визита) и прикрепить промокод. Каналы: push, email, SMS. Статистика: доставлено, прочитано, кликнуто, использовано промокодов. Каждая рассылка содержит обязательную ссылку отписки. Ограничения: не более 3 рассылок в неделю от одного владельца; один гость не может получить более 1 сообщения за 3 дня (антиспам).

**Автосценарии:**
Предустановленные автоматические коммуникации, которые владелец может включить:
- Благодарность после визита
- Запрос отзыва
- Напоминание о повторном визите (через 30 дней)
- Реактивация «потерянных» гостей (не было визитов > 90 дней)
- Поздравление с днём рождения (если гость указал)

Каждый сценарий можно кастомизировать (текст, время отправки, канал) или отключить.

**Шаблоны ответов.**
Готовые шаблоны для быстрых ответов на сообщения клиентов: «Спасибо за бронирование!», «К сожалению, на эту дату занято, предлагаем...», «Ждём вас!». Владелец может создавать собственные шаблоны.

## 2.13 Административная панель

Единый центр управления платформой для администраторов, модераторов, финансистов и операторов поддержки. Включает следующие разделы:

- **Управление пользователями:** поиск и просмотр профилей клиентов и владельцев, блокировка аккаунтов (при блокировке: завершение всех сессий, заморозка кошелька, деактивация листингов), разблокировка, ручная верификация.
- **Управление бронированиями:** просмотр, ручная отмена, ручной возврат, изменение статуса.
- **Управление кошельками:** просмотр балансов, ручное начисление/списание, заморозка средств.
- **Управление контентом:** модерация листингов и отзывов (FR-143–146).
- **Справочники:** типы объектов, удобства, праздники по регионам, категории — добавление, редактирование, удаление.
- **Промо и маркетинг:** управление промокодами, реферальной программой, подарочными сертификатами, программой лояльности.
- **Настройки платформы:** сервисный сбор (по регионам и категориям), политики отмены, антифрод-правила, фичефлаги (включение/отключение функций), SLA для поддержки, лимиты кошельков, тарифы владельцев.
- **Антифрод-дашборд:** мониторинг подозрительных операций, правила, алерты (FR-раздел 5.15).
- **RBAC (ролевая модель):** управление ролями администрации, назначение прав, обязательная 2FA для всех админов.
- **Операционные дашборды:** аналитика (FR-147–154), поддержка и споры, модерация.
- **Регионы:** управление регионами, валютами, платёжными провайдерами.
- **Центр уведомлений администрации:** уведомления о критических событиях (антифрод, SLA нарушения, финансовые расхождения) по ролям, email-дайджест.
- **Массовые операции:** одобрение/отклонение листингов, блокировка пользователей, начисление бонусов — до 1 000 записей за одну операцию.
- **Аудит-лог:** запись всех действий администрации (кто, что, когда), с возможностью поиска и корреляции.

## 2.14 Безопасность и антифрод

**Антифрод клиента:**
- Более 3 пополнений кошелька с разных банковских карт за 24 часа → автоматический флаг аккаунта, уведомление безопасности.
- Цепочка «пополнение → бронирование → отмена» более 2 раз за 7 дней → блокировка кошелька до ручной проверки (подозрение на отмывание).
- Баланс кошелька > 50 000 ₽ при отсутствии бронирований за 30 дней → флаг для проверки.

**Антифрод владельца:**
- Самобронирование (владелец бронирует свой объект) → немедленная блокировка бронирования и флаг аккаунта.
- Более 3 выводов в день малыми суммами (дробление) → флаг для проверки.

**Антифрод платформы:**
- Обнаружение фейковых листингов (несуществующие объекты, украденные фото).
- Попытки обхода платформы (передача контактов через мессенджер для оплаты напрямую).
- Аномальные паттерны отмен (массовые отмены от одного пользователя или по одному объекту).

## 2.15 Личный кабинет владельца

Единый рабочий интерфейс владельца, включающий:

- **Дашборд:** сводная статистика (бронирования сегодня, доход за период, рейтинг, баланс), быстрые действия, уведомления.
- **Управление объектами:** список листингов, статусы, действия (редактирование, деактивация, дублирование).
- **Управление бронированиями:** входящие запросы, подтверждённые, активные, история. Одобрение/отклонение, фиксация прибытия/убытия.
- **Финансы и выплаты:** баланс кошелька, история транзакций, вывод средств, автовывод, акты, отчёты.
- **Продвижение:** создание рекламных кампаний, установка бюджета и ставки, статистика эффективности.
- **Настройки:** личные данные, уведомления, 2FA, API-интеграции, CRM-настройки, кошелёк.
- **Пустые состояния:** на каждом экране, где ещё нет данных (нет бронирований, нет отзывов, нет гостей в CRM), отображается поясняющий текст с призывом к действию (например, «У вас пока нет бронирований. Убедитесь, что листинг активен и заполнен»).
- **Управление сотрудниками:** владелец может пригласить сотрудников (менеджер / наблюдатель) по email. Менеджер — может управлять бронированиями и отвечать на сообщения. Наблюдатель — только просмотр. Доступ можно ограничить по конкретным объектам (если у владельца несколько). Все действия сотрудников — в аудит-логе. Доступ можно отозвать в любой момент.

## 2.16 Масштабирование

**Выход в новый регион:**
Поэтапный процесс: анализ рынка и локальных требований → локализация (валюта, язык, платёжный провайдер, фискализация) → привлечение первых владельцев (ассистированный онбординг) → запуск → мониторинг 90 дней (метрики предложения, спроса, качества).

**Тарифные планы:**
Архитектура позволяет добавлять новые тарифные планы для владельцев и клиентов через админ-панель без доработки кода.

**Категории объектов:**
Справочник типов объектов расширяется через админ-панель. Возможность добавить новые категории (например, «термальные источники», «японская баня»).

**API-интеграция с PMS:**
Для крупных объектов и сетей — интеграция с системами управления: Yclients, Restoplace. Двусторонняя синхронизация бронирований и расписания.

**Исходящие вебхуки для владельцев:**
Владелец может настроить вебхуки для получения уведомлений о бронированиях, отменах и оплатах в свою CRM-систему или мессенджер.

## 2.17 SEO и индексация

- **Open Graph** — мета-теги для красивого превью при шаринге в соцсетях и мессенджерах (фото, название, описание объекта).
- **Schema.org (JSON-LD)** — структурированная разметка для Google: тип объекта, рейтинг, цена, адрес. Повышает видимость в поиске.
- **sitemap.xml** — автоматически обновляемая карта сайта для поисковых роботов.
- **ЧПУ-URL** — человекочитаемые адреса: `/minsk/sauna-relax-na-partizanskom` вместо `/listing?id=12345`.
- **SSR (серверный рендеринг)** — публичные страницы (каталог, карточки, отзывы) рендерятся на сервере для корректной индексации поисковиками.
- **Диплинки** — ссылки, которые открывают нужный экран в мобильном приложении (когда оно будет) или в браузере.

## 2.18 Профиль клиента

Личный кабинет клиента включает:

- **Личные данные:** имя, фото, email, телефон, регион. Редактирование в любой момент.
- **История бронирований:** все бронирования с фильтрацией по статусу (активные, завершённые, отменённые). Быстрые действия: повтор, отмена, изменение, открытие спора.
- **Избранное:** сохранённые объекты (до 100).
- **Промокоды:** активные промокоды и их условия.
- **Реферальная ссылка:** уникальная ссылка для приглашения друзей, статистика приглашений и бонусов.
- **Кошелёк:** баланс, история, пополнение, информация о бонусах и сроках сгорания.
- **Лояльность:** текущий статус, прогресс до следующего уровня, история начислений кэшбэка.
- **Пустые состояния:** на каждом экране без данных — пояснение и призыв к действию (например, «Вы ещё ничего не бронировали. Найти баню рядом?»).

# 3. БИЗНЕС-ПРАВИЛА И ОГРАНИЧЕНИЯ

## 3.1 Региональные правила

| Клиент | Листинг | Валюта | Результат |
|--------|---------|--------|-----------|
| BY | BY | BYN | ✅ Разрешено |
| RU | RU | RUB | ✅ Разрешено |
| BY | RU | — | ❌ Запрещено |
| RU | BY | — | ❌ Запрещено |

**Инвариант:** кросс-региональные бронирования запрещены. Клиент из Беларуси бронирует только объекты в Беларуси (BYN), клиент из России — только в России (RUB).

## 3.2 Правила кошелька

- **Бонусные средства** (promo, cashback, welcome_bonus, referral) — маркетинговые скидки. Не подлежат выводу, не возвращаются при отмене. При удалении аккаунта — сгорают. Имеют срок жизни (по умолчанию 180 дней).
- **Реальные средства** (topup) — деньги, внесённые клиентом с карты. При удалении аккаунта обязательно возвращаются на исходный инструмент. Бессрочные.
- **Подарочные сертификаты** (gift_cert) — предоплаченные сертификаты. Срок жизни 12 месяцев. При удалении аккаунта — неиспользованный остаток сгорает.

## 3.3 Геополитические ограничения

- Раздельная платёжная инфраструктура для РБ и РФ (разные провайдеры, разные валюты, разная фискализация).
- МИР и СБП — только РФ. БЕЛКАРТ, ЕРИП — только РБ.
- Два инфраструктурных кластера с общей админ-панелью; каждый может работать автономно (если один недоступен — второй продолжает работать).

# 6. РЕЕСТР БИЗНЕС-РЕШЕНИЙ

| № | Вопрос | Решение |
|---|--------|---------|
| 1 | Запрет вывода с кошелька клиента vs возврат на карту при отмене | Возврат на карту = прямой refund от эскроу через провайдера, НЕ вывод с кошелька. Если с кошелька → на кошелёк. Комбо → пропорционально. |
| 2 | Mobile-first vs нет нативных приложений | Первый релиз = адаптивный веб. Push через Web Push. Нативные — в плане. Критичные уведомления → SMS. |
| 3 | Фиксация прибытия vs неявка | Фиксация = обязательно (для определения неявки). Кнопка + push-напоминание. |
| 4 | 18+ платформа vs возраст объекта | Регистрация: 18+. Мин. возраст объекта ≥ 18. |
| 5 | Тарифы для владельцев | Два тарифа: Бесплатный и Платный. 0% комиссия. Монетизация через подписку. |
| 6 | Лимит кошелька | Максимальный баланс: 100 000 ₽ / 3 000 BYN. |
| 7 | Кросс-региональные бронирования | Запрещены. BY→BY, RU→RU. |
| 8 | Кросс-региональная конвертация при смене региона | Не поддерживается. Баланс потратить до смены. |
