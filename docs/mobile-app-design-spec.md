# ТЗ для дизайнера: мобильное приложение RelaxHUB

Документ описывает полный набор экранов, их содержимое, состояния и поведение для мобильных приложений RelaxHUB (iOS + Android, single codebase, портретная ориентация). Разделён на два продукта: **Клиент** (B2C) и **Владелец/Представитель** (B2B). Документ — постановка задачи на проектирование макетов и интерактивного прототипа.

Базируется на:
- `docs/BRD_RelaxHub_v7.md` — бизнес-требования (источник правды по логике)
- `design/` — RelaxHUB Design System (палитра, типографика, компоненты `M*` для мобильных)
- `design/mobile-*.jsx` — существующие наброски (Home, Search, Listing, Bookings, Profile, Booking, Ticket, Chat, Wallet, OwnerToday/Calendar/Inbox/Stats)

Существующие наброски — отправная точка; задача — довести до production-ready макетов и спроектировать недостающие экраны.

---

## 0. Общие требования

### 0.1 Платформы и форматы
- **iOS 15+**, **Android 9+ (API 28+)**
- Нативные паттерны: системный шрифт (SF Pro / Roboto) или брендовый из дизайн-системы; native back-gesture iOS, аппаратный back на Android
- Базовый размер артбордов: **iPhone 14/15 — 393×852**, **Android — 412×892**, проверка на **SE3 (375×667)** и больших (430×932)
- Safe area, динамический island, нижний хоум-индикатор — учесть на каждом экране
- Тёмная и светлая темы — обязательны
- Локализации: **RU** (основная), **BY** (русский, региональные различия в валюте/сценариях). Архитектура макетов должна позволять подмену строк без перевёрстки

### 0.2 Дизайн-система
- Использовать токены и компоненты из `design/RelaxHUB Design System.html` и `design/mobile-primitives.jsx` (`MIcon`, `MPage`, `MCard`, `MHeader`, `MTag`, `MButton`, `MPhoto`, `MAvatar`, `MTabBar`, `MStars`)
- Любой новый компонент должен попасть в библиотеку Figma в раздел Mobile/*
- Сетка: 4-pt baseline, отступы экрана 16, между карточками 12, внутри карточек 12/16
- Тач-таргеты: минимум 44×44 (iOS) / 48×48 (Android)

### 0.3 Базовые принципы UX
- Один экран — одна цель; CTA всегда на видимом без скролла участке
- Вся валюта — **рубли с пробелом-разделителем** (`2 500 ₽`) для RU, **BYN** для BY. Никаких копеек на UI (на бэке хранится в копейках)
- Время — `HH:MM`, дата — `Сб, 20 апр`, длительные диапазоны — `Сб, 20 апр · 19:00–23:00`
- Пустые состояния — с иллюстрацией, объяснением и CTA (не голый «Ничего не найдено»)
- Skeleton-loaders для всех списков; pull-to-refresh где уместно
- Все сетевые ошибки — toast + кнопка «Повторить»; критические — full-screen error state

### 0.4 Навигация
- **Клиент**: нижний таб-бар из 5 пунктов — `Главная`, `Поиск`, `Бронирования`, `Сообщения`, `Профиль`
- **Владелец**: нижний таб-бар из 5 пунктов — `Сегодня`, `Календарь`, `Объекты`, `Финансы`, `Профиль`. CRM/Аналитика/Промо доступны из профиля и из карточки объекта
- Стек экранов внутри таба независимый; смена таба сохраняет позицию скролла
- Модальные шиты (bottom sheet) — для фильтров, выбора, действий «поделиться/скопировать/отменить»; full-screen модалка — для wizard-флоу (создание брони, регистрация объекта)

### 0.5 Состояния, которые рисуем для каждого экрана
1. **Default (с данными)**
2. **Empty** (нет данных)
3. **Loading** (skeleton)
4. **Error** (сеть/сервер)
5. **Offline** (если экран должен работать без сети)
6. **Permission denied** (для гео, push, камеры)

### 0.6 Доступность
- Контраст текста ≥ 4.5:1 (WCAG AA)
- Поддержка Dynamic Type (iOS) / Font scale до 1.3× (Android) — текст не должен ломать вёрстку
- Все интерактивные элементы — с accessibility-label
- Не использовать цвет как единственный носитель смысла (статусы — иконка + текст + цвет)

## 1. Универсальные системные экраны

### 1.1 Splash
- Логотип по центру, фон — фирменный градиент.
- Под логотипом — индикатор загрузки.
- Показывается ≤ 1.5 c. Если больше — переходит в «failed to start» с CTA «Повторить».

### 1.2 Онбординг (3 слайда)
1. «Парные на любой случай» — иллюстрация сауны, заголовок, подзаголовок
2. «Бронируйте за минуту» — иллюстрация календаря
3. «Подарочные сертификаты и бонусы» — иллюстрация кошелька
- Низ: пагинация-точки, кнопка «Далее» / «Начать», ссылка «Пропустить».
- Показывается один раз (флаг в storage).

### 1.3 Запросы разрешений
Отдельные экраны pre-prompt **до** системного диалога:
- **Геолокация** — «Покажем парные рядом» (просим только при первом входе в Поиск)
- **Push** — запрашиваем **только после первой завершённой брони** (NB! BRD §2.8)
- **Камера** — при загрузке документов KYC, аватара, фото-доказательств в спорах

### 1.4 Ошибки и оффлайн
- Полноэкранные состояния: `Ошибка сети`, `Сервер недоступен`, `Версия устарела — обновите приложение`
- Toast-уведомления — внизу экрана, 3 секунды, с возможностью «Отменить» где применимо

### 1.5 Force-update / soft-update
- При указании из бэка `min_supported_version` — full-screen блокировка с CTA «Обновить» (deeplink в стор)
- Для soft-update — баннер вверху главной, dismissible

## 2. Аутентификация и онбординг аккаунта

### 2.1 Стартовый экран входа
- Hero-иллюстрация / лого
- Кнопки: «Войти по номеру», «Войти через VK», «Войти через Yandex», «Войти через Google»
- Низ: «Условия и Политика конфиденциальности» (ссылки)

### 2.2 Ввод номера телефона
- Селектор страны (флаг + код). По умолчанию определяется по гео/SIM
- Поле телефона с маской
- Чекбокс «Согласен с офертой и обработкой ПДн»
- CTA «Получить код»
- Состояния: невалидный номер, нет согласия, rate-limit ответом «Слишком много запросов, попробуйте через X сек»

### 2.3 Ввод OTP
- 6-значный код, авто-проксимити SMS на iOS, Android Autofill
- Таймер «Отправить ещё раз через 60 с»
- 3 попытки → блокировка ввода + сообщение
- Под полем — «Изменить номер»

### 2.4 OAuth-возврат
- Веб-вью / system browser возвращает с токеном; индикатор «Заходим…»
- Если профиль новый — переход на «Завершите регистрацию»

### 2.5 Завершение регистрации
- Имя, фамилия, дата рождения (для возрастной верификации 18+), пол (опционально)
- Согласие с офертой и оператором ПДн
- Реферальный код (опционально, можно вставить вручную)
- CTA «Готово» → создание кошелька + welcome-бонус → success-экран «Вам начислено 500 ₽ бонусов» (RU) / «15 BYN» (BY)
- Клиент / Владелец — выбор типа аккаунта на этом же шаге (две карточки с описанием)

### 2.6 2FA (TOTP + SMS)
- **Настройка**: экран «Включить двухфакторную защиту» → отображение QR + ручного ключа → ввод 6-значного кода → backup-коды (10 шт., с экспортом в файл/копированием)
- **Вход с 2FA**: после OTP — экран «Введите код из приложения» (или fallback SMS)
- **Восстановление**: ввод backup-кода

### 2.7 Восстановление пароля (для админ/представителей по email)
- Email → письмо со ссылкой → новый пароль → toast «Все сессии завершены»

### 2.8 Блокировка аккаунта
- Full-screen: «Ваш аккаунт временно заблокирован. Причина: …. Свяжитесь с поддержкой».
- CTA «Написать в поддержку»

## 3. Клиентское приложение

### 3.1 Главная (`Главная`)

#### Содержание
- **Header**: приветствие («Привет, Иван»), иконка уведомлений со счётчиком, переключатель региона (RU/BY) — компактный
- **Поиск-бар** (sticky): «Куда поедем?» + иконка фильтров. Тап → экран Поиска
- **Лента блоков** (вертикальный скролл):
  1. **Сторис/подборки** (горизонтальный скролл круглых карточек): «Last minute», «Новинки», «Премиум», «До 2000 ₽»
  2. **Last-minute банер** — крупная карточка с акцией (если есть)
  3. **Рекомендуем для вас** — горизонтальный скролл `MCard` (фото, имя, район, цена, рейтинг, теги)
  4. **Недавно просмотренные** — горизонтальный скролл (только если есть)
  5. **Сертификаты** — промо-блок «Подарите вечер близкому»
  6. **Реферальная программа** — компактный баннер «Приведи друга — получите по 500 ₽»
  7. **Популярное в городе** — список карточек

#### Состояния
- Empty (нет рекомендаций для нового юзера) → показываем «Популярное» + CTA «Выберите интересы»
- Loading skeleton
- Геолокация выключена → шапка-баннер «Включить геолокацию для подборок рядом»

### 3.2 Поиск (`Поиск`)

#### 3.2.1 Главный экран поиска (список + карта-переключатель)
- **Header**: поле поиска по названию/городу/улице с автокомплитом, кнопка фильтров (показывает счётчик активных)
- **Чипы быстрых фильтров** (горизонтальный скролл): «На сегодня», «Last minute», «До 3000 ₽», «На дровах», «С бассейном», «4+ человек»
- **Переключатель «Список / Карта»** (segmented)
- **Сортировка** (chips/sheet): «Рекомендуем», «Дешевле», «Дороже», «Рейтинг», «Ближе»
- **Список** карточек (вертикально), pagination/infinite scroll
- **Карта** (полноэкранная): пины с ценой, кластеры; снизу — выезжающая карточка выбранного объекта (peek 30%, expand to 80%)
- FAB «Сюда поедем» в режиме карты — поиск по текущему viewport

#### 3.2.2 Sheet «Фильтры»
Полностраничный bottom-sheet с поэтапным скроллом:
- Город / район / станция метро
- Дата и время (date + range slider от 1 до 12 ч)
- Гости (counter: взрослые/дети)
- Цена (двухсторонний slider)
- **Тип** объекта (баня, сауна, хамам, термы, чан, фуродо)
- **Топка** (на дровах / электричество / газ)
- **Удобства** (бассейн, купель, парная, душ, чан, барбекю, караоке, бильярд, проектор, мангал, чан с травами…)
- **Площадь** (м², range)
- **Вместимость** (range)
- **Особое**: с животными, для детей, аренда целиком, верифицированные фото, инстант-бронирование
- **Изохрон / время в пути** — отдельная карточка «Найти в радиусе X минут от точки» (вход на изохрон-экран)
- Низ: «Сбросить» / «Показать N результатов» (sticky CTA)

#### 3.2.3 Изохрон / поиск по времени в пути
- Карта с выбором точки (моя локация / адрес / точка на карте)
- Селектор транспорта: пешком / авто / общественный
- Слайдер «X минут» (5/10/15/20/30/45/60)
- Кнопка «Построить зону» → закрашенная зона + объекты внутри
- Низ — список объектов внутри зоны

#### 3.2.4 Пустой результат поиска
- Иллюстрация, «Ничего не нашли»
- Подсказки: «Расширить дату», «Сбросить фильтры», «Показать в соседнем городе»

#### 3.2.5 Сравнение объектов
- Запускается из карточки результата по чек-боксу «Добавить в сравнение» (макс. 3)
- Плавающая панель внизу со счётчиком и CTA «Сравнить»
- Экран сравнения: горизонтальный скролл колонок (фото, цена, рейтинг, площадь, вместимость, удобства, политика отмены, отзывы)
- Различия подсвечены акцентом

#### 3.2.6 Сохранённые поиски
- На главном поисковом экране (или из меню) — пункт «Мои подписки»
- Список сохранённых: название (auto или custom), фильтры коротко, переключатель push при новых
- Пустое состояние с CTA «Создать из текущих фильтров»

#### 3.2.7 Транспортная доступность
- Доступно из карточки объекта; показывается на отдельном экране-вкладке: метро/автобусы/паркинг с расстоянием

### 3.3 Карточка объекта (`Listing detail`)

#### Структура
- **Галерея** (фото со свайпом, индикатор страниц, иконка «фото проверены», иконки «video» / «360°»)
- **Заголовок**: название, верификация-чек, рейтинг (Bayes) + кол-во отзывов, теги (Хит, Last-min, Новое, Премиум)
- **Адрес**: текст + кнопка «Маршрут», расстояние от меня
- **Кнопки**: «В избранное», «Поделиться», «В сравнение»
- **Цена от**: «от 2 500 ₽/час» + средняя по району
- **Быстрая бронь** (sticky bottom CTA): «Выбрать дату»
- **Вкладки/секции** (анчоры или табы):
  1. **Описание** — текст со «Развернуть»
  2. **Удобства** (иконки + лейблы, группировка: баня/инфраструктура/доп.)
  3. **Залы и парные** (если несколько помещений) — карточки с площадью и фото
  4. **Цены** — таблица: будни/выходные, дневные/вечерние тарифы, доп. гость, сезонные коэффициенты, минимальное время
  5. **Доп. услуги** — список с ценой и единицей (per_hour/per_item/per_person), max 20
  6. **Правила и политика отмены** — gibkaya/moderate/strict с пояснениями
  7. **Расположение** — мини-карта + транспорт
  8. **Отзывы** — общий рейтинг + распределение по 4 критериям (чистота / соответствие / коммуникация / соотношение цена/качество), top-3 отзыва, кнопка «Все отзывы»
  9. **Хозяин** — карточка с именем/аватаром, рейтингом владельца, скоростью ответа, кнопка «Написать»
  10. **Похожие** — горизонтальный скролл

#### Состояния
- Объект на модерации / архивный → баннер «Бронирование недоступно»
- Нет фото — заглушка
- Перегружен — все слоты заняты на ближайшие 7 дней → бейдж «Высокий спрос», кнопка «Уведомить о свободных датах»

#### Экран «Все отзывы»
- Сортировка (новые/полезные/высокие/низкие), фильтр (только с фото, по критерию)
- Карточка отзыва: автор, аватар, дата, общий, разбивка по 4 критериям, текст, фото-сетка, ответ владельца, кнопка «Пожаловаться»

### 3.4 Бронирование (wizard, 4 шага)

Открывается из карточки объекта по «Выбрать дату» / «Забронировать».

#### Шаг 1 — Дата и время
- Календарь (month view, листание); недоступные даты затенены
- После выбора даты — лента слотов (часовые блоки) с ценой каждого слота (ценовая «карта»)
- Слайдер длительности (1–12 ч) или выбор «начало–конец» через двойной тап
- Учитываем буфер/lead-time; «слишком скоро» — disabled с подсказкой
- **Режим бронирования**: instant (без выбора) или request (показываем «Заявка владельцу, ответ в течение N часов»)

#### Шаг 2 — Гости и доп. услуги
- Counter: взрослые / дети
- Чек-лист доп. услуг (с ценой, единицей, лимитом)
- Промо-код / сертификат — поле ввода
- Превью пересчёта цены

#### Шаг 3 — Контакты и пожелания
- ФИО (автозаполнение), телефон, email
- Поле «Комментарий хозяину»
- Согласие с правилами объекта (чек-бокс)

#### Шаг 4 — Оплата
- **Разбивка цены** (раскрывающаяся): база, скидки за длительную сессию, доп. гости, праздничный коэффициент, сезонный, доп. услуги, сервисный сбор, last-minute discount, итого
- **Способ оплаты**: карта, СБП, кошелёк, комбо (кошелёк + карта со слайдером распределения), Apple Pay / Google Pay, MIR, Belkart/ERIP (BY)
- **Сохранённые карты** (если есть) — список с last4 + бренд, иконка «+ Новая карта»
- **Страховой депозит** (если задан): «С карты будет временно удержано до X ₽»
- **Hold для request-mode**: «Деньги спишутся только после подтверждения хозяином»
- CTA «Оплатить N ₽»

#### Экран ожидания / SCA
- Спиннер «Оплачиваем», 3D-Secure поверх (web-view)
- Тайм-аут — кнопка «Отменить»

#### Success-экран
- Анимация / иллюстрация
- «Бронирование подтверждено» (instant) / «Заявка отправлена. Ответ до HH:MM» (request)
- Кратко: дата/время, объект, итог
- CTA: «К билету», «На главную», «Поделиться»

#### Failed-экран
- Причина (insufficient funds / 3DS denied / antifraud)
- CTA: «Попробовать снова», «Связаться с поддержкой»

### 3.5 Бронирования (`Бронирования`)

#### 3.5.1 Список
- Табы: **Активные** / **История** / **Заявки**
- Карточка брони: фото объекта, имя, дата/время, статус-чип (`pending`, `pending_owner`, `confirmed`, `cancelled`, `rejected`, `completed`, `no_show`, `force_majeure_cancelled`), итоговая сумма, код брони (`RH-XXXX`)
- Pull-to-refresh

#### 3.5.2 Детали брони
- **Hero**: фото + статус с пояснением (для `pending_owner` — таймер «Ответ до HH:MM»)
- **Билет** (см. 3.5.3) — кнопка «Открыть билет»
- **Дата/время + кнопка «Добавить в календарь»** (iOS Calendar / Google Calendar / .ics-export)
- **Маршрут** — карта + кнопка «Построить»
- **Состав** — гости, доп. услуги, комментарий
- **Цена** — детальная разбивка
- **Действия**:
  - `Изменить` (max 3 раза/бронь, при ≥24 ч до начала; sub-actions: изменить дату/время, гостей, услуги — отправляется владельцу)
  - `Продлить` (за 1–2 ч до окончания, при наличии свободного слота, 30 мин таймаут от владельца)
  - `Отменить` (с расчётом штрафа по политике + предупреждением)
  - `Жалоба / спор` (для completed)
  - `Повторить` (rebook) — для completed
  - `Чат с хозяином`
  - `Поделиться` (deep-link `/share/booking/:token`)
- **Чек-ин/чек-аут**: окно «Прибыть до HH:MM» + кнопка «Я приехал» (geolocation match 200 м); чек-аут по факту окончания
- **No-show оспаривание** — для статуса `no_show` в течение 2 ч появляется CTA «Оспорить» с заявкой и фото-доказательством

#### 3.5.3 Билет / QR
- Полноэкранный билет: код брони, QR (для сканирования владельцем), дата/время, имя, объект, доп. услуги
- Кнопка «Сохранить в Wallet» (Apple Wallet / Google Wallet)
- Brightness авто-увеличение

#### 3.5.4 Изменение (модалка)
- Wizard: что меняем → новые параметры → пересчёт цены (доплата / возврат) → отправка
- Отдельный экран «Заявка на изменение отправлена», статусы (ожидает / принято / отклонено / истекло)

#### 3.5.5 Отмена
- Полноэкранная модалка с расчётом удержания (по политике), причиной (radio: не подходит время / нашёл другое / форс-мажор / другое), полем комментария, CTA «Отменить бронь» (red)

### 3.6 Сообщения (`Сообщения`)

#### 3.6.1 Список диалогов
- Поиск по имени объекта/хозяина
- Список: аватар (объект), имя, последнее сообщение, время, бейдж непрочитанного
- Свайп: «Архив», «Удалить»

#### 3.6.2 Чат
- Header: аватар, имя объекта, статус «онлайн / был в HH:MM», иконка телефона/инфо
- Сообщения (свои справа, чужие слева), пузырьки с временем, иконка прочтения
- Системные сообщения (изменение брони, отмена) — отдельные стилизованные карточки прямо в потоке
- Поле ввода: вложение (фото из галереи/камеры), эмодзи, отправить
- Бейдж «Сообщение содержит запрещённый контент» — при срабатывании content-filter (BRD §2.8)
- Quick-replies (для владельца — шаблоны), для клиента — нет

#### 3.6.3 Push-чат
- Banner на топе при получении сообщения вне чата

### 3.7 Кошелёк

Доступен из Профиля и из шага оплаты.

#### 3.7.1 Главный экран кошелька
- **Баланс**: крупное число + валюта + переключатель «Реальные / Бонусы» (две вкладки или единый split с подписями)
- **Сгорание бонусов**: карточка «250 ₽ сгорят 12 мая», крупно ближайшее
- **CTA**: «Пополнить», «Подарочный сертификат», «Реферальная программа»
- **История операций**: tx-list (top-up, payment, refund, cashback, bonus, expiry, certificate_redeem) — иконка, заголовок, дата, сумма (зелёная +/красная −)
- Фильтр по типу + датам

#### 3.7.2 Пополнение
- Сумма (предустановки 500 / 1000 / 3000 / 5000 + ручной ввод; диапазон 500–30 000 ₽; cap баланса 100 000 ₽)
- Способ: карта/СБП/Apple Pay/Google Pay
- Сохранённые карты
- CTA «Пополнить»

#### 3.7.3 Подарочные сертификаты
- Вкладки: «Купить», «Активировать», «Мои»
- Покупка: выбор номинала (1/2/3/5/10 тыс), оформление подарка (имя получателя, поздравление, дата отправки), способ оплаты, кому отправить (e-mail / Telegram / ссылка)
- Активация: ввод кода `BANI-XXXX-XXXX`, частичное погашение поддерживается, валидность 365 дней
- Мои сертификаты: список с балансом и сроком

#### 3.7.4 Реферальная программа
- Личный код + кнопка «Поделиться»
- Статистика: приглашено / завершили первую бронь / начислено
- Подсказка «500 ₽ обоим после первой завершённой брони друга»

#### 3.7.5 Промо-коды
- Список активных, ввод нового, истёкшие — отдельным разделом

### 3.8 Уведомления (центр)
- Открывается из иконки колокольчика или вкладки в Профиле
- Список с фильтром по категориям (бронирования, платежи, маркетинг, система)
- Каждое — иконка, заголовок, текст, время; тап → deeplink
- Mark-all-as-read; настройки канал/тип в профиле

### 3.9 Профиль (`Профиль`)

#### 3.9.1 Главный
- Шапка: аватар, имя, телефон, статус-лояльности (бронза/серебро/золото/платина) с прогрессом до следующего уровня
- Pinned: «Кошелёк», «Мои бронирования»
- Список:
  - Личные данные
  - Адреса (для пром-кодов / гео-фильтров)
  - Документы и KYC (если требуется для каких-то функций)
  - Способы оплаты (сохранённые карты)
  - Безопасность (2FA, сессии)
  - Уведомления (настройки каналов)
  - Регион (RU/BY) — переключение
  - Язык
  - Тема (System/Light/Dark)
  - Реферальная программа
  - Поддержка
  - О приложении (версия, оферта, политика)
  - Удалить аккаунт
  - Выйти

#### 3.9.2 Личные данные
- ФИО, дата рождения, пол, e-mail, телефон (смена через OTP), аватар (камера/галерея)

#### 3.9.3 KYC (если включится для клиента — например, для крупных сертификатов)
- Тип субъекта (для клиента обычно «physical», но может быть SP)
- Загрузка документа (паспорт): фото камера + селфи
- Статусы: `pending`, `approved`, `rejected` (с причиной), `expired`

#### 3.9.4 Способы оплаты
- Список карт (last4, бренд, дата истечения, default)
- Add card → вебвью провайдера → возврат
- Удаление с подтверждением

#### 3.9.5 Безопасность
- Включить/выключить 2FA
- Backup-коды
- Управление сессиями: список устройств (имя/ОС/город/последняя активность) + «Завершить сессию» / «Завершить все»

#### 3.9.6 Настройки уведомлений
- Группы (бронирования, чат, платежи, маркетинг, система)
- Per-event × per-channel (push / email / SMS / telegram / in-app) — checkbox-grid
- Mandatory события — выключение задизаблено с подсказкой

#### 3.9.7 Регион (RU ↔ BY)
- Текущий регион + список с условиями переключения
- Чек-лист blocker'ов: ненулевой баланс / активные брони / открытые споры / неактивированные сертификаты — каждый с ссылкой «Решить»
- CTA «Сменить регион» (disabled пока есть blocker'ы)
- Подтверждение «Текущий кошелёк будет архивирован, программа лояльности обнулится»

#### 3.9.8 Удаление аккаунта
- Объяснение «30 дней grace, можно восстановить»
- Чек-лист условий (нет активных броней)
- Ввод кода из SMS
- Финальное подтверждение
- Экран «Аккаунт будет удалён DD.MM.YYYY. Вы можете восстановить его в любой момент до этой даты», CTA «Восстановить»

### 3.10 Поддержка

#### 3.10.1 Главный экран поддержки
- FAQ-бот: поле «Опишите проблему» → варианты ответов
- Категории: Бронирования, Платежи, Объект, Аккаунт, Прочее

#### 3.10.3 Создание тикета
- Категория, приоритет (auto), тема, описание, прикрепить фото/видео/чек
- Связать с бронью (опционально)

#### 3.10.4 Тикет (детали)
- Статус (`new`, `in_progress`, `waiting_user`, `resolved`, `closed`), уровень (L1/L2/L3), SLA-таймер
- Чат с поддержкой
- Кнопка «Закрыть» / «Эскалировать»

### 3.11 Споры

#### 3.11.1 Открытие спора
- Из брони со статусом `completed` — CTA «Открыть спор» (доступно 72 ч после check-out)
- Wizard: причина (radio: не соответствует / грязно / небезопасно / no-show хозяина / другое), описание, доказательства (фото/видео/скриншоты/GPS/чеки)

#### 3.11.2 Карточка спора
- Статус (`opened`, `evidence_collection`, `under_review`, `resolved`, `appealed`)
- Таймлайн событий
- Чат с поддержкой и второй стороной
- Резолюция: full/partial/no refund + компенсация
- Кнопка «Обжаловать» в течение 7 дней после resolved

### 3.12 Жалобы
- Из карточки отзыва / объекта / пользователя — кнопка «Пожаловаться»
- Sheet с категориями (спам, оскорбления, фейк, мошенничество, другое)

- Доступно из Главной/Поиска (иконка-сердечко)
- Отдельный экран «Избранное»: список карточек, группировка по «Папкам» (опционально)

- Открытие `/share/booking/:token` без авторизации показывает мини-карточку (объект, время, кому), с CTA «Открыть в приложении»

## 4. Приложение владельца / представителя

### 4.1 Сегодня (`Сегодня`)

- **Header**: текущий день, переключатель объектов (если несколько; селектор-шит)
- **KPI-чипы** (горизонтальный скролл): «Сегодня броней», «Доход», «Заполненность %», «Новые сообщения»
- **Текущая загрузка** (timeline по часам): полосы занятости с кодом-цветом по статусу
- **Ближайшая бронь**: карточка с гостем, временем, услугами, кнопкой «Заселить» / «Связаться»
- **Список броней дня**: статус, время, гость, итог
- **Виджет действий**: «Заявки» (счётчик), «Чат» (счётчик)
- **Алёрты**: новый отзыв, низкий рейтинг, фрод, штрафы, истечение оферты — вверху как карточки

### 4.2 Календарь (`Календарь`)

- Переключатель **Месяц / Неделя / День**
- **Месяц**: ячейки с заполненностью heatmap (0/частично/полностью), бейдж кол-ва броней
- **Неделя/День**: timeline с блоками-бронями по часам; multi-resource (несколько помещений)
- Тап на брони → детали (см. 4.3.2)
- Тап на свободном слоте → «Заблокировать» / «Создать бронь вручную»
- Sticky низ: «Заблокировать диапазон» / «Открыть продажи»

### 4.3 Бронирования

#### 4.3.1 Список
- Табы: **Заявки (pending_owner)** / **Подтверждённые** / **Сегодня** / **Завершённые** / **Отменённые**
- Карточка: гость (имя/аватар/рейтинг клиента), объект, дата/время, статус, итог
- Search + фильтры (статус, период, объект)

#### 4.3.2 Детали брони (вид владельца)
- Гость: имя, телефон, рейтинг, ссылка на CRM-карточку
- Состав: гости, услуги, комментарий
- Цена: разбивка, ваш payout (после комиссии и фискалки), статус escrow
- Чек-ин/чек-аут: статус, кнопка «Подтвердить заезд» (сканер QR)
- Действия:
  - Для `pending_owner`: «Принять» / «Отклонить» (с причиной)
  - Изменения (одобрить/отклонить запрос клиента)
  - Продление
  - Отменить (с предупреждением о штрафе 10% и репутации)
  - Поставить «no-show»
  - Чат с гостем
  - Создать invoice / чек

#### 4.3.3 Новая заявка
- Полная карточка + sticky bottom: «Принять» / «Отклонить» (radio причин)

#### 4.3.4 Запросы изменений и продлений
- Карточка с diff (старое → новое), доплата/возврат, кнопки Accept/Reject, таймер автоотклонения

### 4.4 Объекты

#### 4.4.1 Список объектов
- Карточки: фото, статус (`draft`, `pending_moderation`, `active`, `paused`, `archived`), полнота заполнения %, текущая загрузка
- FAB «Добавить объект»

#### 4.4.2 Wizard создания/редактирования (7 шагов)
1. **Основное**: тип, название, описание, теги
2. **Адрес и геометка**: ввод + перетаскивание пина
3. **Помещения и площадь**: парные/комнаты отдыха/доп.зоны (повторитель)
4. **Удобства**: чек-боксы из словаря (бассейн, купель, чан…)
5. **Фото и видео**: загрузка, выбор обложки, переупорядочивание; «отправить на верификацию»
6. **Цены и доступность**: базовый тариф/час, дни/времена, мин. длительность, буфер, lead-time, advance, политика отмены, режим (instant/request)
7. **Доп. услуги**: до 20 шт. (название, цена, единица, лимит)

- Каждый шаг сохраняется как draft локально + на бэке
- Submit → отправка на модерацию (если объект готов)

#### 4.4.3 Карточка объекта (детали для владельца)
- Виджеты: статус, рейтинг, отзывы, выручка/мес, загрузка
- Действия: Редактировать, Дублировать, Деактивировать/Активировать, Архивировать, История правок, Audit-log
- Чек-лист «Полнота заполнения» с прогрессом (обязательное / опциональное) — блокирует submit при <100% required

#### 4.4.4 Цены (экран на объект)
- Базовый тариф
- Правила (priority list, drag-to-reorder): диапазон дат / дни недели / часы / коэффициент. Чипы: «Будни», «Выходные», «Праздники», «Сезон», «Доп. гость»
- Smart-pricing: рекомендация коэффициента 0.8–1.5 (toggle «Применять автоматически»)
- Праздничные коэффициенты (default 1.5×) — список со switch
- Last-minute скидки
- Превью «Сколько получит клиент за бронирование 4 ч в субботу»

#### 4.4.5 Календарь объекта (под-экран Календаря)
- См. 4.2; внутри объекта показываем только его слоты
- Кнопка «Импорт iCal» / «Экспорт iCal» (`.ics` ссылка)

#### 4.4.6 Фото и медиа
- Менеджер: upload, drag-reorder, обложка, удаление
- Бейдж «Проверены» / «На проверке» / «Отклонены» (с причиной)
- Вход в «Заказ профессиональной фотосъёмки»

#### 4.4.7 Заказ фотосъёмки
- Карточка с тарифом
- Запрос → подтверждение менеджером → дата → выполнено
- Списание с кошелька владельца

### 4.5 Финансы (`Финансы`)

#### 4.5.1 Главный
- **Баланс кошелька владельца** (доступно к выводу + в холде)
- Карточки: «Доход за месяц», «Средний чек», «Сервисный сбор удержан», «В escrow»
- CTA: «Вывести», «Настроить автовывод»
- Переключатель периода (день/неделя/месяц/произв.)

#### 4.5.2 История транзакций
- Список: тип (booking_payment, payout, refund, fee, fine, ad_spend, photo_order), дата, сумма, статус
- Тап → детальный экран
- Фильтр + экспорт CSV

#### 4.5.3 Вывод средств
- Сумма (с автоподстановкой «всё доступно»)
- Способ: SBP (для RU с привязанным телефоном — мгновенно) или банковский перевод
- Реквизиты (привязанные карты/счета)
- Лимиты: «Сегодня доступно X / Y», «В этом месяце X / Y»
- Комиссия — если применима
- CTA «Вывести»
- Success/Failed экраны

#### 4.5.4 Настройки автовыплаты
- Switch
- Порог суммы
- Расписание (каждый день / при достижении порога)
- Реквизиты по умолчанию

#### 4.5.5 Escrow и удержания
- Список броней в escrow, дата автовыпуска, статусы
- Карточка спора-блокера

#### 4.5.6 Реквизиты для выплат
- Тип субъекта (individual / sole_proprietor / self_employed / legal_entity)
- ИНН, КПП (для ЮЛ), реквизиты счёта, банк, БИК
- Загрузка документов
- Статус верификации

#### 4.5.7 Фискализация
- Настройки провайдера (none / atol)
- Журнал чеков (статус, ссылка на чек)
- Ручная отправка чека

#### 4.5.8 Финансовые отчёты
- PDF/CSV/1C-XML экспорт за период
- Акты для ЮЛ
- Сверка банковских выписок (CSV/XML импорт, mismatch-список)

#### 4.5.9 Штрафы
- Список (отмены / низкий response rate), сумма, причина

### 4.6 Чат и заявки

#### 4.6.1 Чаты
- Список (как у клиента, но с разделителями по объектам)
- Шаблоны ответов (макс 50): создание, переменные `{{guest_name}}`, `{{date}}` и т.п.
- Quick-replies в чате

### 4.7 CRM

#### 4.7.1 Гости
- Поиск, фильтры (новый/постоянный/потерянный/VIP/др.р. близко)
- Карточка гостя: ФИО, телефон, кол-во визитов, LTV, средний чек, последняя бронь, теги, заметки
- Действия: «Написать», «Создать бронь», «Тег», «В сегмент»

#### 4.7.2 Сегменты
- Список (системные + кастомные)
- Конструктор кастомного: условия (Visits >, LTV >, Last visit >, RFM-параметры)
- Кол-во гостей в сегменте

#### 4.7.3 Рассылки
- Создание: канал (push/email/SMS/telegram), сегмент, шаблон, расписание (сразу/отложенно)
- Превью с подстановкой переменных
- Лимиты: 3/неделя на владельца, 1/3 дня на гостя
- Метрика после отправки: доставлено, прочитано, кликнуто

#### 4.7.4 Авто-сценарии
- Шаблоны: «Спасибо после визита», «Запрос отзыва», «Возвращайтесь (через X дней)», «Реактивация (потерянные)», «День рождения»
- Switch + параметры (через сколько дней, текст, канал)

#### 4.7.5 Шаблоны ответов
- CRUD, до 50 шт.

### 4.8 Аналитика

#### 4.8.1 Главный
- Период-селектор
- KPI-плитки: выручка, бронирования, средний чек, заполненность, конверсия, повторные визиты, NPS/рейтинг
- Графики (line/bar) для каждой метрики
- Сравнение с прошлым периодом (delta)

#### 4.8.2 По объектам
- Сравнительная таблица объектов
- Тап → детали по объекту

#### 4.8.3 Бенчмарки
- «Вы vs средний по району/категории»

#### 4.8.4 Экспорт
- PDF / CSV

### 4.9 Промоушн / реклама

#### 4.9.1 Подписка
- Free / Premium / Promoted — карточки с фичами и ценой; CTA «Перейти»
- Premium даёт +10 boost в выдаче, Promoted — первая позиция

#### 4.9.2 Промо-кампании (аукцион)
- Создание: объект, дневной бюджет (мин 50 ₽), макс. ставка, период, цели
- Список активных, статистика: показы, клики, бронирования, ROI
- Auto-pause при исчерпании бюджета

### 4.10 Профиль владельца

#### 4.10.1 Главный
- Аватар, имя, рейтинг владельца, response-rate
- Список:
  - Бизнес-данные (юр. сущность, реквизиты)
  - KYC-документы (статус)
  - Оферта и доп. соглашения (версия, дата принятия)
  - Реквизиты выплат
  - Регион
  - Представители (см. 4.10.3)
  - Webhooks (см. 4.10.4)
  - PMS (см. 4.10.5)
  - Безопасность (2FA, сессии)
  - Уведомления
  - Подписка
  - Поддержка
  - О приложении
  - Удалить аккаунт / Выйти

#### 4.10.2 KYC и оферта
- Загрузка документов, статус, история
- Принятие новой версии оферты — модальное окно при входе

#### 4.10.3 Представители
- Список (имя, email/телефон, роль, права)
- Пригласить (отправка ссылки)
- Управление правами (per-объект): просмотр / редактирование / приём заявок / финансы

#### 4.10.4 Owner Webhooks
- До 20 эндпоинтов
- Поля: URL, секрет, события (5 типов: booking.created/confirmed/cancelled/completed, payment.received), включён
- Логи доставки (последние N) с retry-статусом

#### 4.10.5 Интеграции PMS
- Yclients / Restoplace
- Привязка по credentials (encrypted)
- Кнопки «Синхронизировать сейчас», лог последней синхронизации
- Включение событий (SyncBookings/Schedule, Push/Pull)

#### 4.10.6 Онбординг владельца (отдельный пре-флоу)
- Шаги после регистрации: KYC → подписать оферту → реквизиты выплат → создать первый объект
- Прогресс-бар на главной до завершения

### 4.11 Поддержка владельца
- Аналогично клиенту (3.10), приоритеты могут быть выше; категории: Бронирования, Финансы/выплаты, Модерация, Технические, Другое

### 4.12 Уведомления (центр) для владельца
- Категории: заявки, заказы, платежи, модерация, финансы, маркетинг, система, антифрод-алёрты

## 5. Кросс-роль системные элементы

### 5.1 Push-уведомления (тексты)
Дизайнер должен предусмотреть **карточки push** с иконкой приложения и payload-полями. Тексты:
- Клиент:
  - «Бронь подтверждена» / «Заявка принята» / «Заявка отклонена»
  - «Напоминание: завтра в 19:00 — Берёзовая роща»
  - «Время идёт — отметьтесь о заезде»
  - «Бонусы 250 ₽ сгорят через 3 дня»
  - «Новое сообщение от хозяина»
  - «Платёж не прошёл»
- Владелец:
  - «Новая заявка от гостя»
  - «Оплата получена»
  - «Запрос на изменение»
  - «Гость не явился — отметьте»
  - «Новый отзыв ★4.5»
  - «Низкий рейтинг — внимание»

### 5.2 In-app банеры
- Промо-баннер (главная клиента) — фон, заголовок, подзаголовок, CTA, изображение справа
- Алёрт-баннер (главная владельца) — иконка, заголовок, описание, CTA

### 5.3 Bottom-sheets шаблоны
- Выбор из списка (одиночный/множественный)
- Подтверждение действия (заголовок, описание, primary, secondary)
- Поделиться (нативный share-sheet или кастомный с иконками каналов)

### 5.4 Toast-шаблоны
- Success (зелёный), Info (нейтральный), Warning (жёлтый), Error (красный) — иконка + текст + опциональная кнопка-действие

### 5.5 Skeleton-шаблоны
- Карточка объекта, строка списка, блок с фото/текстом, чат-сообщения
