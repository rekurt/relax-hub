# Subsystem 11: CRM for Owners (FR — section 2.12)

## Overview
Guest cards with auto-tracking, predefined segments, broadcast messaging to segments, auto-scenarios (automated messages on events), and response templates for quick replies.

## Context
- Existing booking data: `internal/service/booking_service.go` — tracks all bookings per client/bathhouse
- Existing chat: `internal/service/chat_service.go` — real-time messaging
- Existing notifications: `internal/notification/` — push, email, telegram channels
- Owner role manages bathhouses via AccessChecker
- No CRM functionality exists currently

## Dependencies
- Depends on: Booking system (existing) — for guest visit tracking
- Depends on: Notification system (existing) — for broadcasts and auto-scenarios
- No dependencies on other NEW subsystems

## Development Approach
- **Testing approach**: Regular (code first, then tests)
- **CRITICAL: every task MUST include new/updated tests**
- **CRITICAL: all tests must pass before starting next task**
